# ADR-0021: WATCH 현재 상태의 별도 조회와 재점검

- 상태: 채택
- 결정일: 2026-09-05

## 결정

역할 자료의 연결 상태는 기존 워크스페이스 프로젝션과 다른 API로 조회한다. 서버에서 이벤트를
누적 적용하는 상태 저장소를 추가하지 않고 WATCH의 현재 GET 응답을 사용한다. 인박스의
`eventId`는 중복 제거에만 사용하고 `sourceRevision`이나 이벤트 도착 순서로 건강 상태를 정하지 않는다.
인박스의 불변 저장·접수증·보존 정책은 그대로 유지한다.

공유 키와 자료 소유권, 종료·보관 여부 및 최신 아웃박스의 URL을 네트워크 호출 전후의 짧은
트랜잭션에서 확인한다. 두 확인 사이에는 DB 트랜잭션을 유지하지 않는다. 원본 변경이나 권한 거부를
이전 상태로 가리지 않는다. 조회 실패·누락·리비전 불일치·오래된 결과는 `UNKNOWN`이며 자료는 유지한다.

조회·재점검 전용 HTTP 클라이언트는 기존 아웃박스 전달기의 긴 시간 예산과 분리한다.
동시 4건·대기열 없음, 연결 1초·읽기 2초, 본문 8KiB와 리디렉션 금지를 적용한다.
동시성 한도가 찼을 때 추가 요청을 쌓지 않고 조회 불가 또는 재점검 일시 오류로 응답한다.
재점검도 원격 리비전과 원본을 다시 대조해 확인 시점에 동기화가 덜 된 자료의 요청을 보류한다. WATCH GET과 POST는 원자적 요청이 아니므로 그 사이의 동시 변경을 잠그지는 않는다. 새 상태 저장 테이블이나 마이그레이션은 필요하지 않다.

React Query가 팀·시즌·자료·공유 키·URL별 조회를 관리한다. 열린 상세 화면만 30초 주기로
조회하고 요청 중단 신호를 전달한다. 재점검 접수는 결과를 미리 정상으로 바꾸지 않는다.

## 선택 이유와 한계

이벤트만으로 최신 상태를 재구성하려면 별도 상태 순번과 양쪽 서비스의 계약 변경이 필요하다.
현재 상태 조회는 이 순서 문제를 만들지 않고 기존 자료 응답과 다른 화면 작업에도 영향을 줄인다.
대신 열린 상세의 조회 트래픽이 생기고 최대 30초의 화면 갱신 지연이 있다. WATCH 조회 실패는
연결 실패와 구별하며 마지막 점검이 5분 이상 오래되면 상태 확인이 필요하다고 표시한다.

동일 소스 리비전의 다른 URL은 GET이 URL을 노출하지 않아 식별할 수 없다. 독립 복원에서는
WATCH 복구 도구로 기존 불변 스냅샷을 같은 리비전으로 PUT해 전체 페이로드의 일치까지 확인한다.
운영 공개 HTTPS·콜백·자격 증명 검증은 로컬 구현 및 테스트와 구분한다.
