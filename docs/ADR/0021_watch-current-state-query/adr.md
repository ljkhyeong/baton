# ADR-0021: WATCH 현재 상태의 별도 조회와 재점검

- 상태: 채택
- 결정일: 2026-09-05

## 결정

역할 자료의 연결 상태는 기존 워크스페이스 프로젝션과 다른 API로 조회한다. 서버에서 이벤트를
누적 적용하는 상태 저장소를 추가하지 않고 WATCH의 현재 GET 응답을 사용한다. 인박스의
`eventId`는 중복 제거에만 사용하고 `sourceRevision`이나 이벤트 도착 순서로 건강 상태를 정하지 않는다.
인박스의 불변 저장·접수증·보존 정책은 그대로 유지한다.

공유 키와 자료 소유권, 종료·보관 여부 및 최신 아웃박스의 URL을 네트워크 호출 전후의 짧은
트랜잭션에서 확인한다. 두 확인 사이에는 DB 트랜잭션을 유지하지 않는다. 원본 변경이나 권한 거부를
이전 상태로 가리지 않는다. 조회 실패·누락·리비전 불일치·오래된 결과는 `UNKNOWN`이며 자료는 유지한다.

최신성은 WATCH의 `lastConclusiveAt`을 기준으로 주입한 UTC `Clock`과 비교한다. 판정이
없으면 `UNKNOWN/PENDING`, 정확히 5분 전이거나 더 오래된 판정은 `UNKNOWN/STALE`이다.
판정이 있는데 시도가 없거나, 시도가 미래이거나, 판정이 시도보다 뒤면 `STALE`로 처리한다.
`lastCheckedAt`은 최근 시도 완료 시각으로 별도 전달하며 화면에 두 시각을 나누어 표시한다.
`INTERNAL_FAILURE`는 WATCH에서 기존 건강 상태와 판정 시각을 유지하므로 시도 시각을
최신성 기준으로 쓰면 오래된 정상 상태가 계속 유효해지는 문제가 있다. 시도 시각으로
판정 시각을 대체하지 않으며 WATCH 자체의 기본 10분 상태 만료는 변경하지 않는다.

현재 원본과 일치하는 최근 결과의 `lastOutcome`와 `consecutiveFailures`를 별도 조회 응답에
함께 전달한다. `AVAILABLE`이 아니면 두 값을 `null`로 반환한다. WATCH가 계산한 상태·횟수를
BATON에서 다시 계산하지 않고 고정 코드로 실패 원인을 안내한다. 원격 예외 메시지나 본문을
전달하지 않으며, 점검 서비스 내부 오류를 대상 링크의 새 실패로 표시하지 않는다.

조회·재점검 전용 HTTP 클라이언트는 기존 아웃박스 전달기의 긴 시간 예산과 분리한다.
인스턴스당 조회 연결 3건과 재점검 POST 연결 1건을 분리한다. 동시 조회는 진행·대기·중복
요청을 합쳐 최대 32건이며, 서로 다른 자료는 공정한 세마포어에서 최대 1초만 기다린다.
같은 자료의 진행 중인 GET은 한 번만 보내고 중복 요청은 최대 4초 기다린다. 완료 결과를 캐시하지
않으며 각 호출자의 권한·원본·리비전 대조는 계속 수행한다. 상한 초과나 대기 만료는 기존 조회
불가로 반환한다. POST는 별도 1건 상한에서 대기 없이 실패한다. 연결 1초·읽기 2초,
본문 8KiB와 리디렉션 금지는 유지한다. HTTP 요청 자체의 전체 경과 시간 제한을 새로 추가한 것은 아니다.
재점검도 원격 리비전과 원본을 다시 대조해 확인 시점에 동기화가 덜 된 자료의 요청을 보류한다. WATCH GET과 POST는 원자적 요청이 아니므로 그 사이의 동시 변경을 잠그지는 않는다. 새 상태 저장 테이블이나 마이그레이션은 필요하지 않다.

React Query가 팀·시즌·자료·공유 키·URL별 조회를 관리한다. 열린 상세 화면만 30초 주기로
조회하고 요청 중단 신호를 전달한다. 브라우저별 WATCH 상태 GET은 동시 2건, 시작 간격 최소
250ms로 분산하며 최대 100건을 대기시킨다. 대기부터 응답까지 30초 상한을 두고 실제 전송에는
기존 API 클라이언트의 10초 상한도 적용한다. 화면 닫기·변경 시 대기 및 진행 조회를 취소한다.
완료 응답을 별도 전역 캐시에 복제하지 않는다. 여러 서버 인스턴스나 브라우저 전체를 합친
전역 요청 속도 제한은 아니며 인그레스 제한에 걸린 요청은 여전히 조회 불가가 될 수 있다.

React Query의 `staleTime`만으로 오래된 데이터가 삭제되지는 않으므로 화면이 `isStale`과
`isPaused`, `onlineManager`의 연결 상태를 확인한다. 오프라인과 30초가 지난 조회 캐시의
상태 배지·실패 원인·횟수는 현재 결과로 표시하지 않고 새 결과 확인 여부도 갱신하지 않는다.
조회 오류가 없는 기존 캐시의 판정·시도 시각은 유지한다. 조회 오류일 때는 이전 응답의 상세 정보도 숨긴다.
캐시 자체를 지우거나 서버의 5분 판정 규칙을 프런트에서 복제하지 않는다.
별도 만료 타이머를 만들지 않고 쿼리 관찰자의 만료 알림을 사용한다. 공용 QueryClient의
다른 기능 설정은 변경하지 않는다. WATCH 조회에만 탭 복귀·재연결 시 항상 재조회를 적용한다.

`상태 새로고침`은 기존 GET과 조회 대기열을 사용한다. 진행 중에는 버튼을 잠그고
`cancelRefetch: false`로 같은 조회를 취소·재시작하지 않는다. 읽기 실패 뒤 다시 사용할 수
있으며 편집 제한에도 허용한다. 오프라인에서는 조회·재점검 버튼을 비활성화하고 재점검
예약 POST를 새로 보내지 않는다. 캐시가 만료된 동안에도 재점검 버튼은 비활성화한다.
자료별 `role="status"` 영역은 수동 조회의 진행·결과와 표시 상태·제외 사유 변경을 알린다.
자동 조회가 같은 상태를 반환하면 시각·횟수 갱신을 반복해서 알리지 않는다. 닫힌 상세는
`aria-live="off"`로 알림을 끄며, 알림 문구는 화면의 상태·사유 문구를 사용한다.

편집 허용 여부와 조회 여부를 분리한다. 바통 전달·충돌 복구 대기로 편집이 잠겨도 열린 상세의
상태 조회는 유지하고 서버의 가용 상태를 표시한다. 수동 재점검 버튼의 기존 편집 제한은 유지한다.
종료 시즌의 자동 점검 제외 여부도 편집 상태로 추측하지 않고 서버 응답을 따른다.

사유 없는 빈 감시 조회 결과를 `monitoringReason`과 활성 스냅샷으로 구분한다. 원본의
감시 제외 사유는 `NOT_MONITORED`, 아직 등록 정보가 없거나 현재 주소와 맞지 않는 경우는
`PENDING/SYNC_PENDING`으로 반환한다. 적격성 판단은 아웃박스 기록의 기존 정책을 재사용하며
권한·소유권 검사 뒤에 수행한다. 조회 중 자료·시즌 상태가 바뀌면 변경 후 사유를 우선한다.

재점검 접수는 결과를 미리 정상으로 바꾸지 않는다. 접수 뒤 버튼을 30초 동안 잠그고,
429 응답에서는 서버의 `Retry-After` 초를 사용한다. 잘못된 대기 초는 30초를 적용한다.
자료별 재요청 시각은 같은 페이지의 React Query 캐시에 보관하고 미사용 캐시는 1시간 뒤에
정리한다. 역할 이동으로 컴포넌트가 다시 생성되어도 남은 시간을 유지하며, 진행 중인 요청도
같은 범위의 mutation 상태로 확인해 중복 접수를 막는다. 팀·시즌·자료·공유 키·URL이 달라지면
별도로 취급한다. 영구 브라우저 저장소나 새 서버 테이블은 추가하지 않는다.
접수 전 조회한 `lastConclusiveAt`보다 새로운 판정을 후속 `AVAILABLE` 조회에서 확인하면
안내를 바꾼다. 이전 판정이 없었다면 최초 판정을 확인한다. 내부 오류로 시도 시각만
갱신됐거나 같은 판정 시각·조회 실패·오래된 결과는 새 결과로 처리하지 않는다. 접수증에 점검 시도 ID가 없으므로
안내는 새 결과를 확인했다는 의미이며 특정 요청과 점검 시도의 일대일 대응을 주장하지 않는다.
접수 내용과 새 결과 확인 여부는 재요청 시각과 같은 범위의 React Query 메모리 캐시에
보관하고 미사용 캐시는 1시간 뒤 정리한다. 이 확인 이력은 현재 연결 상태와 구분하므로
역할 이동 뒤에도 유지하고 오프라인·조회 실패·캐시 만료 때문에 접수 대기로 되돌리지 않는다.
새 재점검을 시작할 때 이전 안내를 초기화하며 URL·공유 키가 바뀌면 별도로 취급한다.
페이지 전체 새로고침과 다른 브라우저까지 접수 안내를 보존하는 기능은 아니다.

## 선택 이유와 한계

이벤트만으로 최신 상태를 재구성하려면 별도 상태 순번과 양쪽 서비스의 계약 변경이 필요하다.
현재 상태 조회는 이 순서 문제를 만들지 않고 기존 자료 응답과 다른 화면 작업에도 영향을 줄인다.
대신 열린 상세의 조회 트래픽이 생기고 최대 30초의 화면 갱신 지연이 있다. WATCH 조회 실패는
연결 실패와 구별하며 마지막 연결 판정이 5분 이상 오래되면 상태 확인이 필요하다고 표시한다.

동일 소스 리비전의 다른 URL은 GET이 URL을 노출하지 않아 식별할 수 없다. 독립 복원에서는
WATCH 복구 도구로 기존 불변 스냅샷을 같은 리비전으로 PUT해 전체 페이로드의 일치까지 확인한다.
운영 공개 HTTPS·콜백·자격 증명 검증은 로컬 구현 및 테스트와 구분한다.
