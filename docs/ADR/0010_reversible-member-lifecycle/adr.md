# ADR-0010: 구성원 활동 종료를 참조 보존형 상태 변경으로 모델링

- 상태: 채택
- 결정일: 2026-07-29

## 배경

BATON의 구성원은 역할의 현재·다음 담당자, 결정 작성자와 역할 인수인계의 이전·다음 담당자·상태별 확인자로 참조된다. 그룹 스터디를 실제 운영하면 참여 종료, 휴식과 복귀가 생기지만, 구성원 행을 삭제하거나 기존 참조를 비우면 과거 역할, 결정과 역할 인수인계의 맥락이 사라진다.

한편 활동을 종료한 구성원을 새 역할 담당자나 새 결정 작성자로 계속 선택할 수 있게 두면 현재 운영과 과거 기록의 경계가 흐려진다. 이름 정정과 활동 상태 변경은 여러 사용자가 같은 공유 링크로 동시에 수행할 수 있으므로 조용한 덮어쓰기도 막아야 한다.

## 결정

### 상태와 이름

- `Member`는 `null`을 허용하는 UTC `deactivatedAt`을 가진다. 값이 `null`이면 활동 중이고, 값이 있으면 활동 종료 상태다.
- 활동 종료와 재활성화는 삭제가 아닌 가역 상태 변경이다. 같은 상태를 다시 요청하면 기존 값을 유지하며 성공한다.
- 구성원 이름은 현재 표시 이름이다. 이름을 수정해도 구성원 UUID와 기존 역할·결정 참조는 유지한다.
- `(team_id, name)` 유일성은 활동 종료 구성원에게도 적용한다. 과거 구성원과 같은 이름을 새 사람에게 재사용해 기존 참조가 모호해지는 일을 막고, 필요한 경우 구분 가능한 별칭을 사용한다.
- 이름 수정은 당시 이름의 역사 스냅샷을 만들지 않는다. 결정의 `authorName`도 현재 구성원 이름으로 다시 결합하므로 과거 화면에 정정된 표시 이름이 보인다.

### 조회와 선택 가능성

- 워크스페이스 조회 모델은 활동 중·활동 종료 구성원을 모두 반환한다. 기존 역할 담당자, 결정 작성자와 역할 인수인계 참여자 표시는 계속 해석할 수 있어야 한다.
- 새 역할의 현재·다음 담당자, 새 결정 작성자와 역할 인수인계의 이전·다음 담당자는 활동 중 구성원만 선택할 수 있다.
- 기존 역할이나 결정을 수정할 때 같은 위치의 기존 활동 종료 구성원 참조를 그대로 유지하는 것은 허용한다. 다른 위치나 다른 기록에 활동 종료 구성원을 새로 배정하는 것은 허용하지 않는다.
- 구성원 활동 종료는 기존 역할, 결정과 역할 인수인계 이력 참조를 변경하지 않는다. 운영자는 활동 종료 표시를 확인하고 필요한 역할의 새 담당자를 별도로 지정한다. 열린 역할 인수인계의 참여자는 전달·수락 시 다시 활동 상태를 검증한다.

### 동시성

- `Member`에 JPA `@Version`을 두고 이름·활동 상태 변경의 겹친 커밋을 `409 WORKSPACE_CONTENT_CONFLICT`로 수렴한다.
- 역할·결정·역할 인수인계에 새로 들어오는 구성원과 역할 인수인계 전달·수락 참여자를 검사할 때 대상 구성원 행을 UUID 순서로 공유 잠금한다. 활동 여부 확인과 역할·결정·역할 인수인계 저장 사이에 구성원 활동 종료가 끼어드는 경쟁을 직렬화한다.
- 잠금 획득 실패도 다른 공유 콘텐츠와 같은 `WORKSPACE_CONTENT_CONFLICT`로 처리한다.
- 저장소 버전은 HTTP 응답에 노출하지 않는다. 오래 열린 화면에서 순차적으로 도착한 전체 수정 요청까지 막아야 한다면 별도 ETag 또는 요청 버전 계약을 검토한다.

### HTTP 표현

- `PUT /api/v1/teams/{teamId}/seasons/{seasonId}/members/{memberId}`는 표시 이름 전체 표현을 수정한다.
- `PATCH /api/v1/teams/{teamId}/seasons/{seasonId}/members/{memberId}/deactivation`은 `deactivated` boolean으로 활동 종료 또는 재활성화를 설정한다.
- 두 요청은 같은 상태를 다시 설정해도 결과가 달라지지 않으므로 생성용 `Idempotency-Key`를 요구하지 않는다.
- 구성원 응답과 워크스페이스 조회 모델은 `null`을 허용하는 `deactivatedAt`을 반환한다.

## 결과

### 장점

- 활동 종료와 재활성화가 역할·결정 이력을 파괴하지 않는다.
- 현재 운영의 선택 후보와 과거 기록을 표시하는 구성원 집합을 분리할 수 있다.
- 이름 중복, 겹친 수정과 활동 종료·신규 배정 경쟁을 서버 경계에서 일관되게 막는다.
- 별도 삭제·복구 API 없이 파일럿 구성원 변화를 운영할 수 있다.

### 비용과 한계

- 활동 종료 구성원이 기존 역할에 남아 있을 수 있으므로 UI가 상태를 표시하고 새 담당자 지정을 안내해야 한다.
- 현재 모델은 이름 정정 전 문자열이나 V13 이전의 과거 역할 배정 변경 이력을 보존하지 않는다. V13 이후 명시적으로 시작한 역할 교대는 `RoleHandoff`에 당시 담당자와 기간을 보존하지만, 직접 역할을 수정한 모든 배정 이력을 일반화하지는 않는다.
- 구성원 잠금 순서와 새 배정/기존 참조 구분을 역할·결정·역할 인수인계의 모든 변경 경로에서 유지해야 한다.
- 영구 삭제와 개인정보 보존 기간은 이 결정의 범위가 아니다.

## 대안

### 구성원 행 삭제

기존 역할·결정 참조가 깨지고 복구가 어려워 채택하지 않았다.

### 활동 종료 시 기존 참조 자동 해제

과거 기록을 현재 운영 편의에 맞춰 재작성하므로 채택하지 않았다.

### 활동 종료 구성원을 조회 모델에서 제외

기존 담당자와 작성자를 표시할 수 없고 클라이언트가 참조를 미정으로 오해하므로 채택하지 않았다.

### 활동 종료 전에 모든 역할 해제 강제

현재 담당 정리는 유도할 가치가 있지만 참여 종료를 불필요하게 막고 결정 작성자 참조까지 해결하지 못하므로 첫 파일럿의 필수 조건으로 두지 않았다.

```bash
./gradlew --no-daemon :application:useCaseTest
./gradlew --no-daemon :adapter-in-web:restDocsTest
./gradlew --no-daemon generateApiContract
cd frontend && npm run build && npm run e2e:smoke
```

V9 데이터의 구성원 참조를 보존한 V10 이관, V13의 역할 인수인계 팀 소속 복합 참조를 위한 `(id, team_id)` 유일 키, 이름 수정과 활동 종료·재활성화, 활동 종료 구성원의 조회 모델·기존 참조 보존, 새 역할·결정·역할 인수인계 배정 거절, 기존 참조를 유지한 수정 허용, 이름·버전·행 잠금 충돌을 확인한다.
