# ADR-0021: 팀별 계정 전환과 구성원 접근 권한

- 상태: 채택
- 결정일: 2026-09-05

## 배경

기존 공유 키는 팀 전체를 읽고 쓰는 권한이다. 계정·구성원 연결만으로 기존 계정을 모두 승인하면
공유 링크를 가진 사람이 선택한 구성원 이름을 관리자 신원으로 승격하는 문제가 생긴다.

## 결정

1. 팀마다 기본값이 거짓인 계정 전환 상태를 둔다. 첫 관리자는 기존 계정 세션·활성 구성원 연결과
   별도 운영자 복구 키를 모두 확인한 뒤 지정한다. 다른 기존 연결은 권한 없는 상태로 보존한다.
2. `AccountTeamMembership`에 팀 권한 `ADMIN`, `MEMBER`, `VIEWER`를 저장한다. 별도 인증 토큰이나
   중복 계정 연결 테이블을 만들지 않는다. 상세 행렬은 PRD-0009가 소유한다.
3. 전환된 팀에서는 `WorkspaceScopeAuthorizer`가 현재 계정·권한·구성원 활동 상태를 검사한다.
   현재 계정 조회 포트는 bootstrap이 웹의 표준 SecurityContext 조회에 연결한다.
4. 권한 변경·초대 수락·구성원 관리와 시즌 관리에는 팀 배타 잠금을 사용한다. 일반 변경은 팀 공유
   잠금 뒤 기존 시즌 잠금을 사용해 권한 회수와 업무 변경의 순서를 보장한다. 마지막 관리자 검사도
   같은 팀 배타 잠금 안에서 수행한다.
5. 초대는 해시만 저장하고 계정 연결·권한 부여·소비를 한 트랜잭션에서 처리한다. 기존 공유 키의
   별도 트랜잭션 연결 경로를 호출하지 않는다. 전환된 팀에서는 구성원을 직접 연결할 수 없다.
6. 세션이 있는 변경 요청은 CSRF와 동일 출처를 검사하고 화면이 확인한 계정을 대조한다.
   계정별 조회 키와 계정 변경 시 캐시 제거를 함께 적용한다.
7. 권한 설정 이력은 별도 불변 행으로 보존한다. 기존에 사용자가 선택한 확인자 이름과 전체 콘텐츠 편집 이력을 소급해
   신원이 검증된 기록으로 취급하지 않는다.
8. 복원된 계정 권한·초대를 자동으로 폐기하지 않는다. 계정 권한 팀을 발견한 복원 스크립트는 완료
   처리를 중단해 운영자가 격리 상태에서 권한을 재확인하도록 한다.

## 결과와 한계

공유 키 파일럿을 유지하면서 팀별로 계정 권한을 도입할 수 있다. 시즌·역할 단위 권한, 계정 병합·탈퇴,
일괄 이메일 초대, 전체 콘텐츠 감사와 계정 팀의 자동 복구는 별도 결정이 필요하다. 계정 팀의 기존
공유 링크와 직접 연결은 즉시 거부되므로 관리자는 전환 전에 다른 구성원의 초대 절차를 준비해야 한다.
