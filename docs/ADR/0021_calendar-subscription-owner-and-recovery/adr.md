# ADR-0021: BATON이 개인 캘린더 구독 소유권과 복구 의도를 보관한다

- 상태: 채택. 운영 활성화와 CAL 후보 계약 공식 채택은 별도
- 결정일: 2026-09-05

## 배경

CAL은 사용자 계정과 워크스페이스 권한을 소유하지 않는다. 생성 응답에만 구독 ID가 있으면
응답을 놓친 BATON은 같은 구독을 찾아 복구할 수 없다. 원문 토큰을 저장해 같은 응답을 재전송하면
일회성 자격 증명 정책이 바뀐다. 구성원 활동 중지도 HTTP 성공에만 의존하면 장애 뒤 구독이 남는다.

## 결정

- BATON이 `(accountId, seasonId)`별 CAL 구독 ID를 외부 호출 전에 저장한다.
- 사용자 API는 계정 세션·워크스페이스 접근 키·시즌과 구성원 자격을 확인한다. CAL 응답 직후에도
  같은 권한을 다시 확인하고 달라졌으면 주소 반환 대신 폐기를 기록한다.
- 발급·회전·폐기는 짧은 저장 트랜잭션의 1분 임대로 직렬화한다. 외부 HTTP는 그 밖에서 호출하고
  현재 요청 토큰으로만 결과를 기록한다. 기존 최대 HTTP 시간 예산 45초보다 긴 임대다.
- CAL PUT 중복 응답은 주소 재노출이나 자동 회전으로 바꾸지 않는다. 사용자가 새 주소 발급을
  선택할 때만 기존 주소를 무효화한다. 토큰과 전체 주소는 DB·로그·조회 캐시·브라우저 저장소에 두지 않는다.
- 활동 중지 원본 변경과 같은 트랜잭션에 구독 폐기 의도를 남긴다. 재활성화가 기존 폐기를 취소하지
  않으며, 전달 작업자는 같은 ID로 재전달한다. 폐기가 완료된 구독의 다음 발급은 새 ID를 사용한다.
- CAL 복구 진단은 현재 불일치 원인과 과거 완료 기록을 보여주는 근거다. BATON 원본의 기대값과
  최종 매니페스트 검증을 대신하지 않는다.

## 결과와 제한

응답 유실·중복 요청·권한 변경 뒤에도 같은 구독을 찾아 복구하거나 폐기할 수 있다.
CAL에 사용자 모델과 BATON DB 접근을 추가하지 않는다. 사용자에게 주소를 다시 보여주려면 재발급과
캘린더 앱의 재등록이 필요하다. CAL이 폐기를 수신하기 전의 지연과 앱에 이미 저장된 일정의 제거는
별개다. 서버 저장 상태와 브라우저 동작은 로컬에서 검증하며 공인 HTTPS와 실제 앱 갱신은 아직 남아 있다.
