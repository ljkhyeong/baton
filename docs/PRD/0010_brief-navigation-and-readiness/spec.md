# PRD-0010: 주간 요약 이력 탐색·현재 업무 연결·생성 준비 상태

- 상태: 채택
- 결정일: 2026-09-05
- 범위: BATON 사용자 화면의 주간 요약 탐색과 원본 업무 연결, 생성 요청 전 안내와 저장 이후 추가 전달 확인, 선택 복원·공유·인쇄

## 목적과 담당 범위

저장된 주간 요약에서 문제를 확인한 사용자가 현재 업무로 이동하고, 지난 기록과 비교하며,
변경사항 전달이 끝났는지 확인한 뒤 이번 주 생성을 요청할 수 있게 한다.

BRIEF는 저장된 주간 요약·생성 이력·비교 기능을 제공한다. BATON은 사용자 권한, 현재 역할·반복 업무와
이벤트 전달·생성 실행 기록을 관리한다. 현재 업무명은 저장된 주간 요약 본문에 추가하지 않으며
기존 주간 요약 ETag·선정 규칙·이벤트 계약·스키마를 바꾸지 않는다.

## 사용자 API

모든 경로는 `/api/v1/teams/{teamId}/seasons/{seasonId}/brief` 아래다. 활동 중 계정 세션과
같은 팀의 활동 중인 구성원 연결을 확인한다. 계정 권한을 사용하는 팀은 기존 팀 권한을, 공유 키 방식의 팀은
작업 공간 접근 키를 검사한다. 종료 시즌도 조회할 수 있다. 원본 업무
일괄 조회는 읽기 전용 POST지만 기존 세션 정책에 따라 동적 CSRF와 동일 출처를 요구한다.
모든 응답은 `Cache-Control: no-store`다.

| 메서드 | 하위 경로 | 의미 |
| --- | --- | --- |
| `GET` | `/editions` | 요약 버전 내림차순의 생성 이력 |
| `GET` | `/editions/{editionId}` | 선택한 주간 요약의 저장된 본문과 ETag |
| `GET` | `/editions/{editionId}/changes?fromEditionId=...` | 기준 요약과 선택한 요약의 차이 |
| `GET` | `/editions/{editionId}/previous-week` | 선택한 요약과 같은 시간대의 지난주 마지막 요약 |
| `GET` | `/editions/{editionId}/delivery-status` | 선택한 주간 요약의 마지막 성공 생성·재사용 경계 이후 추가 전달 여부 |
| `POST` | `/sources/query` | 표시 중인 원본 참조의 현재 업무 이름·이동 대상 |
| `GET` | `/generation-readiness` | 현재 시즌의 변경사항 전달 상태와 요약 생성 가능 여부 |

이력의 `beforeGeneration`은 선택적 양의 배타 커서다. `limit`은 기본 20, 범위 1~100이다.
응답은 BRIEF의 `editions`와 `nextBeforeGeneration`이며 마지막 커서는 null이다. 요약은
`editionId`, `generation`, `weekStart`, `zoneId`, `generatedAt`, `sourceCursor`,
`ruleVersion`, `itemCount`를 포함한다. 화면은 이전 페이지를 더 불러와 주차·요약 버전으로
주간 요약과 비교 기준을 선택한다.

단건 조회는 BRIEF 전체 응답의 팀·시즌과 요청한 `editionId`를 확인한다. 다른 범위는
`404 BRIEF_EDITION_NOT_FOUND`로 존재를 감춘다. 비교는 두 주간 요약의 범위를 먼저 확인한 뒤
기존 BRIEF 비교 API를 호출한다. BRIEF의 비교 범위 검증을 사용자 권한으로 대체하지 않는다.

`added`, `removed`, `changed.before`·`changed.after`는 저장된 값을 그대로 중계한다.
`removed`는 화면에서 ‘제외’로 표시하고 실제 해소·삭제를 추론하지 않는다. `section`만
달라도 분류 변경을 표시하며 각 주간 요약의 저장 시간대와 규칙 버전을 유지한다.

## 보던 화면 복원

같은 계정·팀·시즌·접근 키로 작업 공간을 보고 있는 동안 점검 항목의 상태·심각도·공백 필터,
BRIEF와 저장된 주간 요약의 펼침 상태, 해결 목록의 펼침 상태, 조회할 주간 요약과 비교 기준을
유지한다. 영역을 접었다 펼치거나 현재 업무로 이동한 뒤 ‘오늘’로 돌아와도 같은 선택을 사용한다.
‘지난주와 바로 비교’ 선택도 유지한다.

이 선택은 작업 공간 화면의 메모리에만 둔다. 계정·팀·시즌·접근 키 또는 링크의 주간 요약 선택이
바뀌면 이전 선택을 초기화한다. 새로고침과 새 탭은 공유 링크에 담긴 주간 요약 식별자만 복원한다.
BRIEF 영역을 접었다 펼치거나 업무 화면에서 돌아올 때 현재 점검 목록·해결 목록은 첫
페이지부터 읽고, 상태 변화의 과거 페이지를 복원하지 않는다. 조회 응답·현재 업무명·주간 요약 본문을 브라우저 저장소에 추가하지 않는다.

## 특정 주간 요약 링크

‘요약 링크 복사’는 현재 표시한 주간 요약을 다음 BATON 화면 주소로 복사한다.

`/teams/{teamId}/seasons/{seasonId}?brief={editionId}`

- URL에는 팀 접근 키·세션·서비스 Bearer와 비교 결과를 넣지 않는다. 이 링크 자체가 접근
  권한을 부여하지 않으며 기존 로그인·활성 멤버십·팀 접근 권한 검사를 그대로 적용한다.
- `brief`는 한 건의 UUID만 허용한다. 형식 오류나 중복 값은 잘못된 링크로 안내하며,
  사용자가 링크 선택을 지울 수 있다.
- 로그인 후 돌아올 주소는 기존 작업 공간 경로에 유효한 `brief` 하나가 붙은 경우만 추가로
  허용한다. 외부 경로·fragment·다른 쿼리와 섞인 주소는 로그인 복귀 대상으로 사용하지 않는다.
- 접근이 거부되면 초대 또는 팀 공유 링크로 권한을 확인하도록 안내한다. 계정 권한이 있는
  사용자는 공유 키 없이 접근할 수 있다. 저장소가 막힌 경우에는 기존 새 탭 로그인 흐름을 유지한다.
- 화면에 불러온 이력에 해당 주간 요약이 없어도 단건으로 조회한다. 없음·권한 거부·연결 실패를
  안내하고 최신 주간 요약으로 자동 대체하지 않는다.
- 클립보드 사용이 실패하면 사용자가 직접 복사할 수 있는 읽기 전용 입력란을 제공한다.

## 인쇄와 PDF 저장

‘인쇄·PDF 저장’은 브라우저 표준 인쇄 창을 연다. PDF 저장 여부와 저장 위치는
브라우저에서 선택한다. 출력에는 선택한 주간 요약의 주차, 요약 버전·생성 시각·시간대, 집계 구간,
선정 항목, 원본 참조·리비전·공백 근거, 주간 요약 식별자·수신 커서·규칙 버전을 담는다.

이번 주 변경·이전 주부터 미해결·분류 미기록은 저장된 `section`으로 구분한다. 이전 데이터의
원본 변경 번호·변경 기록 누락의 `null`은 미기록으로 표시한다. 현재 점검 목록이나 해결 요약·비교 화면을 출력에
섞지 않는다. 현재 BATON에서 확인한 업무명은 현재 이름임을 별도로 설명하며 과거 이름으로
표시하지 않는다. 현재 업무 조회가 실패하거나 연결할 수 없으면 이름을 확인할 수 없다고 적는다.

주간 요약 재조회 중에는 공유·인쇄 버튼을 막고, 업무명 조회 중에는 인쇄를 막는다. 인증·권한
거부 시 기존 본문과 함께 출력용 본문도 제거한다. A4 용지 설정은 주간 요약에만 적용하며 여러
페이지에서도 항목을 이어서 출력한다. 기존 바통북 인쇄는 기존 범위를 유지한다.

인쇄 버튼은 출력할 주간 요약 주소에서 접근 키를 제거한 뒤 인쇄를 호출한다. 인쇄 종료나 출력
영역 해제 시, 사용자가 그 사이 다른 주소로 이동하지 않았다면 원래 주소를 복원한다. 이
주소 처리는 기존 바통북 인쇄와 공유한다. 브라우저 메뉴·단축키 인쇄는 버튼의 주소 정리를
거치지 않으므로 주소에 접근 키가 남아 있다면 화면의 인쇄 버튼을 사용한다.

## 지난주와 바로 비교

`GET /editions/{editionId}/previous-week`는 먼저 사용자 권한과 선택한 주간 요약의
팀·시즌·식별자를 확인한다. 저장된 `weekStart`에서 한 주를 빼고 저장된 `zoneId`로 BRIEF의
기존 주간 최신 API를 호출한다. 현재 날짜·현재 시즌 시간대나 화면에 로드된 이력에서 찾지 않는다.

정확한 지난주·시간대 안에서 생성 번호가 가장 큰 주간 요약을 반환한다. 규칙 버전은 제한하지
않는다. 해당 주차가 없으면 `404 BRIEF_EDITION_NOT_FOUND`이며 더 오래된 주차로 대체하지
않는다. 범위 밖 선택 주간 요약도 `404`이고 외부 주간 조회를 수행하지 않는다. 응답 주차·시간대가
요청과 다르면 계약 오류로 처리한다. 성공 본문·ETag·no-store는 기존 저장된 주간 요약과 같다.

‘지난주와 바로 비교’ 버튼으로 찾은 주간 요약을 기존 비교 API의 기준으로 사용한다. 버튼을 다시
누르면 지난주의 마지막 생성 결과를 다시 확인한다. 직접 기준을 선택하거나 조회 중인 요약을
바꾸면 자동 비교 선택을 초기화한다. 없음·연결 실패를 구분하고 이전 비교 내용을 감추며,
권한 거부는 저장된 주간 요약 영역을 감춘다. 규칙이 다르면 기존 규칙 차이 안내를 유지한다.

## 현재 업무 연결

요청은 `sources` 배열에 `eventType`과 `sourceReference`를 담는다. 한 번에 1~100건이며
참조는 빈 값이 아닌 최대 512자다. 이 제한은 BATON의 업무 연결 요청에만 적용하며 BRIEF의
기존 수신·조회 계약을 바꾸지 않는다. 화면은 표시할 참조를 중복 제거하고 100건씩 요청한다.

응답 `sources`는 요청 순서를 유지하고 각 항목에 같은 이벤트 종류·원본 참조와 `target`을 반환한다.
`target`은 현재 이름 `title`, `roleId`, 선택적 `routineId`, 보관 여부 `archived`다.
역할의 routineId는 null이며, 연결할 수 없는 항목의 target도 null이다.

- `baton-continuity:<정규 UUID>`로 저장된 신호를 같은 팀·시즌에서 읽고 eventType까지 확인한다.
- 신호 UUID를 역할·루틴 UUID로 간주하지 않고 저장된 subjectId를 사용한다.
- 역할은 팀·시즌을, 루틴은 시즌과 현재 소유 역할의 팀·시즌을 다시 확인한다.
- 이전 참조, 미존재·삭제, 유형·범위 불일치는 이동 대상을 만들지 않는다.
- 현재 업무 이름은 과거 생성 당시 이름이 아니다. 별도 요청으로 표시하고 과거 주간 요약이나
  비교 결과에 합쳐 저장하지 않는다.
- 역할은 역할 상세로, 인수인계 신호는 해당 역할의 바통 화면으로, 루틴은 운영 화면의 해당
  루틴으로 이동한다. 보관 루틴은 보관함을 펼쳐 이동한다.
- 현재 워크스페이스 화면에 대상이 없으면 새로고침을 안내한다. 브라우저가 임의 URL을 만들거나
  다른 작업 공간으로 이동하지 않는다.

### 상황별 행동과 상세 기록

기존 이동 동작은 유지하고 다음 버튼·안내를 현재 업무 정보와 함께 제공한다. 버튼은 현재
업무 화면을 여는 동작이며, 주간 요약의 과거 문제 상태로 현재 업무를 수정하거나 해소하지 않는다.

| 점검 유형 | 버튼 | 안내 내용 |
| --- | --- | --- |
| `ROLE_UNASSIGNED` | 담당자 확인 | 현재 담당자와 담당 기간 |
| `ROLE_SUCCESSOR_MISSING` | 다음 담당자 확인 | 다음 담당자와 역할을 넘겨줄 기간 |
| `ROLE_PREPARATION_INCOMPLETE` | 인수인계 준비 확인 | 역할 목적·담당 업무와 필요한 자료 |
| `ROUTINE_REPEATEDLY_OVERDUE` | 지연된 업무 확인 | 마감과 회차별 진행 상태 |
| `HANDOFF_INCOMPLETE` | 인수인계 확인 | 남은 항목과 전달·수락 상태 |

보관된 루틴은 ‘보관된 반복 업무 보기’로 표시한다. 그 밖의 종료 시즌·해소 항목은 ‘현재 업무
보기’로 표시하며, 현재 연결 대상을 확인할 수 없으면 버튼을 만들지 않는다. 과거 항목의
담당자 공백이 지금도 유지된다고 추측하지 않는다.

현재 점검·해결 목록과 저장된 주간 요약·비교 결과의 원본 참조와 변경 번호는 각 영역 아래의 ‘연동 상세’에 모아 기본으로 접어둔다. 저장된 요약의 집계 구간·수신 커서·선정 규칙도 같은 영역에 표시한다. 업무 행에는 업무명·상태·시각과 이동 버튼을 표시하며, 인쇄물에는 기존 원본 근거를 유지한다.
상태 전이도 상태·시각·원본 심각도를 먼저 표시하고 리비전·공백 발견은 ‘변경 근거 보기’에서
확인한다. 브라우저 표준 details/summary의 키보드 동작을 사용한다. 화면의 ‘변경 기록 누락’은
기존 revisionGap과 같은 값이며 항목 수를 누락 이벤트 개수로 해석하지 않는다. 필터·목록·
변경 이력·비교·인쇄물은 PRD-0009의 화면 용어를 함께 사용한다. 문서와 화면은 ‘주간 요약’을 사용하며, 생성 순서는 ‘요약 버전’으로 표시한다. 생성 버튼은 ‘이번 주 요약 만들기’이며, 결과가 같으면 ‘내용이 같아 기존 요약을 불러왔습니다.’로 안내한다.

## 저장 이후 추가 전달 확인

`GET /editions/{editionId}/delivery-status`는 기존 계정·활동 중인 팀 구성원·팀 접근 권한을 확인하고,
BRIEF 주간 요약의 팀·시즌·식별자를 검증한 다음 BATON 기록을 조회한다. 범위 밖 주간 요약은 단건과
같이 `404 BRIEF_EDITION_NOT_FOUND`로 처리한다. 저장된 본문을 변경하지 않는 별도 응답이며
`Cache-Control: no-store`를 사용하고 ETag를 만들지 않는다.

응답은 요청한 `editionId`, 아래 `status`, BATON의 `checkedAt`이다.

| 상태 | 판정 |
| --- | --- |
| `ADDITIONAL_DELIVERIES` | 해당 주간 요약을 만들거나 재사용할 때 확인한 범위 이후에 전달 완료된 변경이 있음 |
| `NO_ADDITIONAL_DELIVERIES` | 생성·재사용 성공 기록은 있지만 그때 확인한 범위 이후에 전달 완료된 변경은 없음 |
| `UNKNOWN` | 선택한 주간 요약의 생성·재사용 성공 기록이 BATON에 없음 |

확인 기준은 같은 팀·시즌·`editionId`의 `SUCCEEDED` 실행에 저장된 최대 `deliveryWatermark`다.
같은 주간 요약을 재사용한 성공도 포함하고 `created_new=true`로 제한하지 않는다. 비교 대상은
같은 팀·시즌의 `DELIVERED` 아웃박스 중 ID가 이 경계보다 큰 행이다. 두 값을 같은 SQL 문장의
읽기 범위에서 확인하며 생성·재사용 실행이나 아웃박스를 갱신하지 않는다.

- BRIEF `sourceCursor`·`generation`과 BATON 아웃박스 ID를 비교하지 않는다.
- 생성 시각과 완료 시각의 대소 비교로 판정하지 않는다.
- 대기·처리 중·실패 아웃박스를 전달 완료로 간주하지 않는다.
- 성공 근거가 한 건도 없으면 `UNKNOWN`이다. 응답 유실 후 미확정인 실행은 제외하며,
  다른 성공 기록이 있으면 그 기록을 기준으로 판정한다.
- 추가 전달이 있어도 선정 항목은 같을 수 있다. NO_ADDITIONAL_DELIVERIES도 원본 전체 반영,
  재조정 완료나 추가 이벤트 부재를 보장하지 않는다. 이미 저장된 전달·생성 기록의 범위만 읽는다.
- 생성 가능 여부와 독립적인 안내다. UNKNOWN이나 추가 전달 조회 실패를 생성 불가로
  바꾸지 않으며 실제 생성은 기존 전달 경계·열린 시즌·처리 임대 판정을 따른다.

화면은 선택한 주간 요약별로 상태와 현재 시즌 시간대의 확인 시각을 표시하고 수동 새로고침을
제공한다. 생성·재사용 요청이 끝나면 이 상태도 다시 읽는다. 같은 `editionId`가 재사용돼도
기존 추가 전달 안내가 갱신되어야 한다. 응답 `editionId`는 화면의 요청과 결합해 확인한다.
다른 주간 요약 응답·조회 실패는 이전 안내를 감추고, 권한 거부는 저장된 주간 요약 영역 전체를
감춘다. 종료 시즌에는 이번 주 생성 대신 현재 점검 항목에서 이후 상태를 확인하도록 안내한다.

## 생성 가능 여부

응답은 `status`, `pendingCount`, `failedCount`, `lastDeliveredAt`, `checkedAt`이다.
같은 팀·시즌의 기존 BRIEF 아웃박스를 집계하고, 전달이 끝났으면 현재 주차·시즌 시간대·전달
`deliveryWatermark`에 해당하는 기존 생성 실행을 읽는다. 조회만으로 실행을 선점·생성·재처리하지 않는다.

| 상태 | 의미와 화면 동작 |
| --- | --- |
| `DISABLED` | 서비스 조회 설정 비활성, ‘BRIEF 연동이 꺼져 있습니다’ 안내 |
| `SEASON_ENDED` | 종료 시즌, 조회만 허용 |
| `DELIVERY_FAILED` | 영구 전달 실패가 있어 운영자 확인 필요 |
| `DELIVERY_PENDING` | 전달 대기·처리 중 이벤트가 있어 생성 대기 |
| `GENERATION_FAILED` | 같은 생성 요청의 영구 실패, ‘주간 요약 생성 오류 · 관리자 확인 필요’ 안내 |
| `GENERATING` | 같은 생성 요청이 확인 시각에 처리 중임 |
| `READY` | 전달 완료이며 생성 또는 저장된 결과 재사용을 요청할 수 있음 |

비활성·종료 시즌을 먼저 적용하고 실패 전달은 대기 전달보다 먼저 안내한다. 전달 대기 수는
`PENDING`·`PROCESSING`, 실패 수는 `FAILED` 행의 수다. 마지막 전달 성공 시각은 `DELIVERED`의
최대 completedAt이며 성공 기록이 없으면 null이다. 실패 완료 시각을 성공으로 표시하지 않는다.
전달 성공·확인 시각은 현재 시즌 시간대로 표시하고,
과거 주간 요약의 항목은 각 주간 요약에 저장된 시간대를 유지한다.

`READY`는 원본 전체 재조정·수신 완전성 또는 BRIEF 연결 성공 보장이 아니다. 저장된 이벤트
전달과 생성 실행을 기준으로 한 요청 준비 상태다. BRIEF `sourceCursor`와 BATON 아웃박스 ID를
비교하지 않는다. 화면은 상태를 새로고칠 수 있고 `READY`일 때만 생성 버튼을 활성화한다.
실제 POST 생성은 기존 권한·열린 시즌·전달 경계·처리 임대 판정을 다시 수행한다. 조회 직후 새
이벤트가 생긴 경우에도 기존 409 차단이 유지된다. 생성 성공·실패 뒤 준비 상태를 다시 읽는다.

## 생성 뒤 화면 갱신

요약 생성·재사용에 성공하면 최신 요약·생성 이력·미해결 항목 집계,
현재 점검 목록과 이번 주 해결 결과를 다시 읽는다. 현재 목록의 상태·심각도·공백 필터는
유지하고 목록 커서·선택한 상태 변화·과거 전이 커서·해소 커서는 초기화한다. 해결 목록을
펼친 상태는 유지한다. 생성이 실패하면 이 선택을 초기화하지 않고 기존 준비 상태·추가 전달
안내의 재조회만 수행한다. 저장된 주간 요약을 현재 상태로 덮어쓰지 않는다.

## 검증 기준과 제외 범위

- 애플리케이션은 범위 밖 단건·비교, 활동 종료 구성원, 원본 식별자·업무 소속 불일치와
  생성 가능 여부를 검증한다.
- 기존 MySQL 통합 시나리오는 요청한 항목만 읽는 범위와 전달 집계·처리 임대 조회를 확인한다.
- 추가 전달 판정은 팀·시즌·주간 요약 범위, 성공 근거 없음, 미완료 제외와 같은 주간 요약 재사용에
  따른 기준 갱신을 MySQL에서 확인한다.
- REST Docs와 보안 테스트가 새 사용자 경로·CSRF·필수 입력·null 응답·ETag를 담당한다.
- 기존 HTTPS 교차 서비스 시나리오에서 저장된 이력·비교와 권한 거부, BATON 원본 API로
  생성한 역할 신호의 업무 연결·전달 대기 상태를 확인한다.
- 브라우저는 이력 페이지, 분류 변경, 잘못된 비교 대상 거부, 원본 역할·보관 루틴 이동과
  생성 가능 여부를 확인한다. 추가 전달 안내의 선택 대상 결합·실패·권한 거부, 같은 주간 요약
  재사용 뒤 갱신과 원본 기록 펼치기도 확인한다. 브라우저 검증은 API 대역을 사용한다.
- 영역 접기·업무 화면 왕복 뒤 필터·주간 요약·비교 선택 유지, 이력 밖 주간 요약 링크 조회,
  클립보드 실패의 수동 복사, 로그인 복귀와 잘못된 링크·권한 거부를 확인한다.
- 출력은 여러 페이지의 선택 항목, 현재 업무명 구분, 이전 근거의 null 표시와 다른 화면
  제외를 확인한다. 저장소가 막혀 접근 키가 주소에 남는 경우의 인쇄 전 제거·종료 후 복원과
  기존 바통북 인쇄를 함께 확인한다. 실제 운영체제 인쇄 창과 실기기 저장은 별도 확인한다.

이번 주 해결 요약은 PRD-0009와 BRIEF PRD-0030을 따른다. 자동 주간 생성, RELAY 전달,
공인 HTTPS 배포는 이 기능에 포함하지 않는다.
BRIEF 운영자 API·공개 Caddy 허용 목록·이벤트 계약 팩도 바꾸지 않는다.
