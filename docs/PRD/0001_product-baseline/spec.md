# PRD-0001: BATON 제품 기준선

- 상태: 초기 기준선
- 작성일: 2026-07-20
- 대상: 웹 서비스 MVP와 실제 그룹 스터디 파일럿

## 1. 제품 정의

BATON은 사람이 바뀌어도 역할과 운영의 기억이 이어지게 하는 조직 운영 OS다.

스터디, 동아리, 학생회, 학교 위원회, 회사의 프로젝트 팀과 TF처럼 여러 사람이 반복해서 함께 일하는 조직을 대상으로 한다. 사람 명단이나 할 일만 관리하지 않고, 역할의 목적과 책임, 반복 운영, 결정의 이유, 인수인계에 필요한 맥락을 하나의 흐름으로 연결한다.

## 2. 해결하려는 문제

작은 조직은 별도의 운영 시스템 없이 메신저, 문서, 캘린더와 개인 기억에 의존하기 쉽다. 이때 다음 문제가 반복된다.

- 해야 할 일이 특정 사람의 기억에 붙어 있어 담당자가 바뀌면 빠진다.
- 반복 업무의 순서와 기준이 매번 다시 논의된다.
- 결정 결과만 남고 이유와 검토했던 대안은 사라진다.
- 인수인계가 임기나 프로젝트 종료 직전에 한꺼번에 이루어진다.
- 누가 떠날 때 끊길 지식과 권한을 미리 발견하기 어렵다.

BATON은 이를 `역할`, `운영 리듬`, `조직의 기억`, `바통`이라는 네 축으로 다룬다.

## 3. 제품 원칙

### 역할이 사람보다 오래 남는다

책임은 사람에게 직접 고정하지 않고 역할에 둔다. 사람은 정해진 기간 동안 역할을 맡는다. 담당자가 바뀌어도 역할의 목적, 책임, 기록은 유지되어야 한다.

### 운영은 반복 가능한 리듬으로 보인다

한 번의 할 일뿐 아니라 모임 전·중·후, 매주, 매월처럼 되풀이되는 운영을 한눈에 확인할 수 있어야 한다.

### 결과와 함께 이유를 남긴다

결정에는 무엇을 정했는지뿐 아니라 이유, 검토한 대안, 영향을 받는 역할을 함께 남긴다.

### 인수인계는 마지막 날의 문서 작업이 아니다

역할을 수행하는 동안 책임, 루틴, 결정, 자료와 위험 신호가 계속 쌓이고, 필요할 때 바통북으로 정리되어야 한다.

### 스터디에서 시작해 더 큰 조직으로 확장한다

첫 실제 사용처는 사용자가 참여하는 그룹 스터디다. 다만 제품 모델은 학교와 회사에도 적용할 수 있도록 조직 종류에 종속되지 않는 용어와 경계를 사용한다.

## 4. 핵심 개념

| 개념 | 의미 |
| --- | --- |
| 팀 | 지속적으로 운영 기록을 소유하는 기본 공간. 스터디, 동아리, 위원회, 회사 팀 등을 모두 포함한다. |
| 시즌 | 학기, 기수, 프로젝트처럼 시작과 종료가 있는 운영 기간이다. 조직의 달력 날짜와 모임·마감 시각을 해석할 IANA 시간대를 가진다. |
| 구성원 | 팀에 참여하는 사람이다. 역할과 동일하지 않다. |
| 역할 | 사람과 분리해 유지하는 목적과 책임의 묶음이다. |
| 역할 배정 | 구성원이 특정 기간 동안 역할을 맡는 관계다. |
| 운영 루틴 | 특정 역할이 반복 수행할 일의 이름, 단계, 기한 문구, 선택적인 실제 마감 규칙과 실행 방법을 담은 정의다. |
| 운영 회차 | 시즌 안에서 사용자가 직접 만들거나 주간·격주 일정이 자동 생성하는 한 번의 운영 단위다. 수동 회차는 메타데이터를 정정할 수 있고, 모든 회차는 실행 기록을 지우지 않은 채 보관·복원할 수 있다. |
| 루틴 실행 | 회차를 만들 때 존재한 루틴 정의와 실제 마감을 복사한 회차별 실행 기록이다. 완료와 시간 상태는 다른 회차와 독립적이다. |
| 결정 기록 | 결정 내용, 이유, 검토한 대안, 작성자와 관련 역할을 담는 조직의 기억이다. |
| 자료 | 역할 수행과 인수인계에 필요한 문서나 외부 링크다. |
| 위험 신호 | 담당자 부재, 개인에게만 있는 지식, 지연된 반복 업무처럼 기억 단절 가능성을 보여주는 단서다. |
| 바통북 | 역할의 목적·책임·루틴·결정·자료·위험과 남은 정리를 모은 인수인계 묶음이다. |
| 역할 바통 | 한 역할의 현재 담당자가 인수인계를 준비·전달·취소하고 다음 담당자가 수락하며 담당 기간을 전환하는 기록이다. |

이 표는 제품 언어의 기준선이다. 데이터베이스 테이블, 상태 열거형, 세부 제약을 확정하는 문서는 아니다.

## 5. 핵심 사용자 경험

### 오늘

사용자는 현재 시즌의 시간대를 기준으로 지금 확인하거나 수행해야 할 예정·진행·지연·완료 루틴과 조직 연속성 위험을 본다. 각 위험은 현재 기록에서 판정한 이유와 바로 취할 다음 행동을 함께 보여 준다.

로그인 계정과 활동 중인 팀 구성원이 연결되어 있으면 `내 담당 업무`에서 현재 담당 역할의 미완료 루틴 실행과 자신에게 전달된 수락 대기 바통을 모아 본다. 보관된 회차와 완료 실행은 제외하고 회차 선택과 관계없이 현재 시즌 전체에서 찾으며, 마감순으로 정렬한다. 루틴은 해당 회차의 운영 화면으로, 바통은 해당 역할의 전달 내용으로 이동한다. 이동한 루틴 또는 바통 본문을 화면에 표시하고 키보드 초점도 함께 옮긴다. 미연결·로그인 필요·활동 종료·조회 실패를 구분하며, 개인화 표시는 공유 키 접근 권한이나 담당자 확인 계약을 바꾸지 않는다.

### 역할

팀이 지속해서 필요로 하는 역할을 만들고 목적, 책임, 현재 담당 기간과 다음 담당자를 확인한다.

### 운영

모임 또는 업무의 전·중·후에 반복되는 루틴을 역할과 실제 마감에 연결하고 이번 회차의 진행 상황을 확인한다. 시즌의 주간·격주 일정을 켜 반복 회차를 자동으로 만들거나 필요할 때 수동 회차를 만든다. 더 이상 반복하지 않는 루틴 정의는 과거 회차의 실행 기록을 유지한 채 보관했다가 복원한다. 잘못 입력한 수동 회차의 이름·날짜는 실행 기록을 유지한 채 정정하고, 현재 운영에서 치울 회차는 생성 방식과 관계없이 보관했다가 복원한다.

### 기록

중요한 결정을 이유와 대안까지 기록하고 관련 역할에서 다시 찾는다. 잘못 입력한 기록은 정정하고, 당장 사용하지 않는 기록은 삭제하지 않고 보관했다가 복원한다.

### 탐색

현재 선택한 시즌의 결정, 바통 항목과 역할 자료를 하나의 시간 흐름에서 검색하고 기록 종류·관련 역할·활성/보관 상태·기간으로 좁힌다. 종료 시즌의 기록은 해당 시즌으로 전환한 뒤 같은 방식으로 탐색한다.

### 바통

역할별 인수인계 준비 상태를 확인하고 책임, 루틴, 결정, 자료, 조언과 남은 작업을 바통북으로 정리한다. 바통 항목도 운영 중 정정하고 보관·복원할 수 있다. 현재 담당자는 다음 담당자와 새 담당 기간을 지정해 바통을 준비하고, 미완료 항목·자료 누락 경고를 확인한 뒤 전달한다. 다음 담당자가 수락하면 역할의 현재 담당자와 담당 기간이 함께 바뀌며, 수락 전에는 현재 담당자가 취소할 수 있다.

바통북 미리보기에는 역할의 목적·책임·주의사항과 활성 루틴·결정·자료, 보관하지 않은 모든 바통 항목을 담는다. 정리 완료한 항목도 내용과 종류를 남기고 미완료 항목 수를 별도로 표시한다. 미리보기의 `인쇄 / PDF 저장` 버튼으로 바통북만 출력하거나 PDF로 저장할 수 있으며, 팀·시즌 이름과 자료 주소를 함께 출력한다. 이 버튼은 인쇄 호출 전에 주소의 접근 키를 제거하고 인쇄 종료·취소 뒤 복원해, 저장소가 막힌 환경에서도 다시 접속할 키를 잃지 않게 한다. 브라우저 메뉴·단축키 인쇄는 이 처리를 거치지 않으므로 키가 주소에 남아 있으면 반드시 미리보기 버튼을 사용하도록 안내한다. 출력물은 현재 조회한 기록의 사본이며 이후 변경을 자동 반영하지 않는다.

### 시즌

팀의 과거·현재 시즌을 전환해 조회하고, 운영 중인 시즌의 이름과 기간을 정정한다. 시즌을 명시적으로 종료하면 기록은 읽기 전용으로 보존한다. 다음 시즌을 시작할 때 이어 갈 역할과 활성 루틴 정의만 선택해 새 식별자로 복사하며 담당자·담당 기간과 실행 상태는 다시 정한다.

## 6. MVP 범위

- 팀과 기간이 있는 시즌을 만든다.
- 시즌의 이름·기간과 종료 상태를 관리하고 필요한 역할·루틴 정의를 다음 시즌으로 이어 간다.
- 구성원과 역할을 분리해 관리하고 역할 담당 기간을 기록한다.
- 역할의 목적, 책임과 반복 루틴을 관리하고 사용하지 않는 루틴 정의를 실행 기록과 분리해 보관·복원한다.
- 시즌 시간대와 주간·격주 일정을 관리하고 반복 회차를 중복 없이 자동 생성한다.
- 루틴의 실제 마감과 이번 운영 회차의 예정·진행·지연·완료 여부를 확인한다.
- 결정 내용, 이유, 대안과 관련 역할을 기록한다.
- 결정의 결과·이유·대안, 바통 항목과 역할 자료를 역할과 시간 흐름으로 다시 찾는다.
- 역할에 자료와 위험 신호를 연결한다.
- 역할별 바통북을 준비하고 현재 담당자의 전달과 다음 담당자의 수락으로 역할 담당자·기간을 전환한다.
- 스터디를 모바일과 데스크톱 웹에서 실제 운영할 수 있다.

알림 시점, 권한 행렬과 보존 기간, 아직 구현하지 않은 영역의 세부 상태값은 실제 파일럿에서 필요한 흐름이 확인된 뒤 별도 결정한다.

### 첫 파일럿 구현 단위

첫 그룹 스터디 파일럿은 전체 MVP 중 다음 세로 흐름을 먼저 사용한다.

- 온보딩에서 한 팀, 한 시즌과 중복되지 않는 이름의 초기 구성원을 함께 만든다. 이름이 같은 사람은 구분 가능한 별칭을 사용한다.
- 운영 중 기존 팀에 구성원을 추가한다. 구성원은 팀에 속하며 앞뒤 공백을 정리한 이름이 팀 안에서 정확히 중복되지 않게 하고, 응답이 유실되면 같은 요청으로 결과를 확인한다.
- 구성원의 현재 표시 이름을 정정하고 활동을 종료하거나 다시 활성화한다. 활동 종료 구성원도 기존 역할·결정 표시를 위해 조회하며, 새 역할 담당자와 결정 작성자 후보에서만 제외한다.
- 워크스페이스 공유 링크를 받은 구성원은 같은 서버 데이터를 읽고 쓴다. 열린 화면은 전경에서 10초마다 최신 워크스페이스를 확인하고, 창으로 돌아오거나 네트워크가 복구되면 즉시 다시 조회한다.
- 역할의 이름, 목적, 담당자, 담당 기간, 책임과 위험 신호를 만들고 운영 중 수정한다.
- 역할에 문서나 외부 자료 링크를 연결하고 제목, URL, 설명과 소유 역할을 운영 중 수정한다.
- 시즌의 반복 루틴 정의와 모임 날짜 기준 실제 마감을 만들고 수정한다. 사용하지 않는 정의는 보관함으로 옮기며 이후 수동·자동 회차와 다음 시즌 선택에서 제외하고, 복원하면 다음 회차부터 다시 포함한다. 보관 이전 회차의 실행은 계속 확인하고 완료 처리할 수 있다. 시즌 IANA 시간대와 주간·격주 일정을 설정하면 `0..30`일 전에 회차를 중복 없이 자동 생성하며 일시 중지·재개할 수 있다. 활성 루틴이 모두 보관된 동안에는 예정 발생일의 커서만 전진시키고 빈 자동 회차를 만들지 않으며, 운영 화면은 활성 루틴을 기다리는 상태를 설명한다. 필요하면 이름과 시즌 안의 모임 날짜를 지정해 수동 회차도 만든다. 생성 시 활성 정의만 복사한 루틴 실행은 회차별로 완료 처리하고 시간 상태는 예정·진행·지연·완료로 구분한다. 수동 회차의 이름·날짜를 정정하거나 어떤 회차든 보관·복원해도 실행 식별자, 스냅샷과 완료 상태는 유지한다.
- 결정 내용, 이유, 대안, 작성자와 관련 역할을 기록하고 운영 중 정정한다. 당장 사용하지 않는 결정은 보관함으로 옮겼다가 복원한다.
- 현재 선택한 시즌의 워크스페이스 프로젝션에서 결정·바통 항목·역할 자료를 통합 탐색한다. 기간은 시즌 시간대의 달력 날짜로 해석하며 자료 URL 문자열과 외부 문서 본문은 검색하지 않는다.
- 역할별 바통 항목을 만들고 내용·분류·소유 역할과 준비 여부를 갱신한다. 당장 사용하지 않는 항목은 보관함으로 옮겼다가 복원한다.
- 역할의 현재 담당자와 다음 담당자, 두 담당 기간을 고정해 역할 바통을 준비한다. 현재 담당자가 미완료 바통 항목과 빠진 자료 경고를 명시적으로 확인해 전달하고 다음 담당자가 수락하면 역할 담당자·기간을 한 번에 전환한다. 수락 전에는 현재 담당자가 바통을 취소할 수 있고, 완료·취소한 이력도 원본 시즌에 남긴다.
- 시즌 이름과 기간을 기존 회차·역할 담당 기간과 열린 역할 바통의 다음 담당 기간 경계 안에서 수정하고, 열린 바통이 없을 때 시즌을 명시적으로 종료하거나 후속 시즌이 없을 때 다시 연다.
- 다음 시즌 시작은 열린 역할 바통이 없을 때 현재 시즌을 종료하고 선택한 역할과 활성 루틴 정의만 새 UUID로 복사한다. 역할 담당자·담당 기간, 보관 루틴 정의, 회차·실행, 결정·바통 항목·역할 바통 이력·자료는 복사하지 않고 원본 시즌에 보존한다.
- 서버가 반환하는 팀 시즌 목록으로 과거 시즌을 전환해 조회한다. 종료 시즌에서는 일반 콘텐츠 변경을 막되 공유·접근 키 관리와 다음 시즌 시작은 유지한다.
- 운영자는 별도 복구 키로 종료 시즌의 이름만 정정할 수 있다. 종료 시각·기간·시간대·계보는 보존하며 일반 화면의 수정 권한은 넓히지 않는다.
- 서버 제품 데이터의 권위 있는 복제본은 MySQL을 단일 기준으로 사용하고 브라우저 `localStorage`와 이중 저장하지 않는다.
- 응답이 유실된 온보딩 재시도는 같은 워크스페이스로 복구되고 중복 팀을 만들지 않는다.
- 기존 팀 구성원·역할·루틴·회차·결정·바통 항목·역할 자료·역할 바통 준비 응답이 유실되어도 같은 요청을 재시도해 이미 생성된 항목을 되찾고 중복 기록을 만들지 않는다.
- 접근 키 회전·복구 응답이 유실되어도 같은 멱등 요청으로 이미 발급된 키를 회수한다. 더 최신 키 변경 뒤 과거 멱등 키를 재사용해 폐기된 링크를 되살릴 수는 없다.
- 백업을 복원하면 스냅샷 시점의 키 폐기 상태를 신뢰하지 않고 모든 팀의 기존 공유 키를 공개 전에 무효화한다. 운영자는 복구 대상 팀마다 새 멱등 키로 접근 키를 재발급하고 새 공유 링크를 다시 전달한다.
- 브라우저는 워크스페이스·콘텐츠 생성과 키 회전 멱등 정보를 요청 전에 내구 저장한다. Web Storage가 예외를 던지면 응답 유실을 안전하게 복구할 수 없으므로 요청을 시작하지 않는다.
- 검증된 워크스페이스는 이 브라우저의 최근 목록에서 다시 열 수 있고, 잘못된 공유 키가 기존 정상 키를 덮어쓰지 않는다.
- 유출된 공유 키를 회전하고, 모든 구성원이 키를 잃으면 생성 권한과 분리된 파일럿 복구 키로 새 키를 복구한다.

공유 링크에는 워크스페이스 접근 키가 URL 프래그먼트로 포함된다. 서버는 원문 접근 키와 워크스페이스·콘텐츠 생성 및 키 변경 멱등 키를 저장하지 않고 SHA-256 기반 해시만 저장한다. 접근 키 원문은 최초 성공 응답과 동일 멱등 요청의 응답 유실 복구 때만 반환된다. 공급자 중립 `Account`와 동일 출처 세션을 도입한 뒤에도 이 키는 기존 워크스페이스 전체를 읽고 쓰는 파일럿 capability(권한 증표)로 남으며 `Account` 세션이 암묵적으로 대체하지 않는다. 조직 초대와 세부 권한으로 전환하기 전까지 링크를 아는 사람은 해당 워크스페이스를 읽고 쓸 수 있다. 따라서 역할 바통의 `confirmedByMemberId`는 이전·다음 담당자 명의의 확인 선언일 뿐 실제 로그인 사용자의 신원을 인증한 감사 증거가 아니다.

다음 항목은 첫 파일럿 구현 단위에 포함하지 않는다.

- 모든 제품 기록의 영구 삭제
- 여러 팀을 한 계정에서 선택하는 화면
- 조직 초대, 역할별 세부 권한과 사용자별 감사 이력
- 계정 비활성화·탈퇴, 비밀번호 재설정과 단계 강화 신원 연결·병합
- 마감·지연을 외부 메시징·메일·캘린더 채널로 보내는 알림

## 7. 현재 구현 상태

현재 프런트엔드는 실제 파일럿 온보딩과 서버 저장 워크스페이스를 제공한다.

- Google·Naver·자체 이메일 계정의 로그인, 자체 이메일 등록·검증과 로그아웃 화면을 제공한다. 인증 정보는 브라우저 저장소의 토큰이 아니라 동일 출처 서버 세션 쿠키로 유지한다.
- 구성원 관리에서 로그인 계정을 기존 활동 중 구성원 한 명과 명시적으로 연결하고, 새로고침 뒤 서버에서 팀별 연결 상태를 다시 확인한다. 연결 사실은 구성원 활동 종료 뒤에도 보존하며, 로그인 복귀 경로에는 워크스페이스 접근 키를 복제하지 않는다.
- 팀, 시즌 기간과 초기 구성원을 등록하고 공유 링크를 만든다.
- 역할 화면에서 현재 팀의 구성원을 추가하고 표시 이름과 활동 상태를 관리한다. 활동 종료 구성원은 기존 역할·결정 기록에 남지만 새 담당자와 작성자 선택에서는 제외하며 다시 활성화할 수 있다. 같은 팀의 중복 이름은 활동 상태와 관계없이 구분 가능한 별칭을 안내하고, 추가 응답 유실 시 같은 멱등 요청으로 생성 결과를 복구한다.
- 오늘, 역할, 운영, 기록, 바통, 탐색 화면을 서버 프로젝션으로 표시한다.
- 파일럿의 오늘 날짜, 시즌 진행률과 종료까지 남은 날짜는 브라우저 위치와 관계없이 시즌의 IANA 시간대에 해당하는 달력 날짜를 기준으로 계산한다. 기존·최초 시즌의 기본값은 `Asia/Seoul`이고 다음 시즌은 원본 시간대를 이어 받는다. 일반 시즌은 시작일에 0%, 종료일에 100%로 표시하며 종료일 다음 날부터 지난 시즌 안내를 보여 준다. 시작일과 종료일이 같은 시즌은 해당 날짜에 `1 / 1주`, 100%로 표시한다.
- 오늘 화면의 조직 연속성 레이더는 현재 담당자 공백, 14일 안의 후임 공백과 바통 미시작, 위험 신호가 있는 역할의 책임·자료·바통 준비 부족, 서로 다른 활성 회차에서 2회 이상 반복한 루틴 지연, 7일 안에 시작하지만 전달·수락이 끝나지 않았거나 현재·다음 담당 기간 사이에 실제 공백이 생기는 역할 교대를 서버에서 계산한다. 활동 종료한 현재·다음 담당자와 진행 단계에 필요한 바통 참여자, 현재 담당자와 같은 후임도 실제 공백으로 보며, 종료 시즌과 보관 회차·보관 바통 항목은 행동 가능한 신호에서 제외한다. 각 신호는 현재 기록에서 판정한 이유와 다음 행동을 함께 표시한다.
- 역할과 루틴 정의·실제 마감을 만들고 수정하며, 역할별 자료 링크를 만들고 수정한다. 루틴 정의는 가역적으로 보관·복원하고 활성 정의만 새 수동·자동 회차에 스냅샷한다. 보관 이전 회차의 실행은 정의 상태와 분리해 계속 표시하고 완료 처리하며, 모든 정의가 보관된 활성 자동 일정은 발생 커서를 전진시키되 빈 회차를 만들지 않고 운영 화면에 `활성 루틴 대기 중`으로 설명한다. 주간·격주 일정은 지정한 선행 생성일에 회차를 자동 생성하고, 오늘 화면은 회차와 루틴을 예정·진행·지연·완료로 나눈다. 수동 회차를 만들고 이름·모임 날짜를 정정하며, 선택한 활성 회차의 루틴 실행을 완료 처리한다. 자동 회차의 이름·날짜는 직접 수정하지 않지만 수동 회차와 마찬가지로 보관·복원할 수 있다. 회차·결정·바통 항목도 가역적으로 보관·복원하고, 결정·바통 항목 내용과 바통 항목 완료 상태를 갱신한다.
- 역할 자료는 링크와 설명을 유지한 채 가역적으로 보관·복원한다. 보관 자료는 일반 역할 화면, 바통 준비의 자료 수, ROUND 방 동작과 WATCH 활성 감시 대상에서 제외하고 역할 자료 보관함과 탐색 기록에는 남긴다.
- 바통 화면에서 역할의 다음 담당자와 담당 기간을 정해 교대를 준비하고, 현재 담당자 명의로 준비도 경고를 확인해 전달한다. 전달된 바통은 다음 담당자 명의로 수락하거나 현재 담당자 명의로 취소하며, 수락하면 역할 담당자와 기간이 함께 갱신된다. 전달 뒤 수락·취소 전에는 역할과 해당 바통 항목·자료 변경 진입점을 막는다.
- 팀의 시즌 목록을 전환해 과거 기록을 조회하고, 활성 시즌의 이름·기간을 정정하거나 명시적으로 종료·재개한다. 종료 시즌은 읽기 전용으로 표시하고 서버도 일반 콘텐츠 변경을 `SEASON_ENDED`로 거절한다. 다음 시즌은 선택한 역할과 활성 루틴 정의만 새 UUID로 복사하고 담당 배정과 실행 상태를 초기화하며, 응답 유실에는 같은 멱등 요청으로 결과를 확인한다.
- 워크스페이스 프로젝션은 루틴 정의·회차·결정·바통 항목의 활성 기록과 보관 기록, 역할 바통 이력을 함께 반환한다. 프런트엔드는 정의·기록의 `archivedAt` 유무로 일반 화면과 보관함을 나눠 새 조회 API 없이 복원하고, 과거 회차는 현재 정의 대신 생성 당시 실행 스냅샷을 표시한다. 따라서 루틴 정의를 보관해도 해당 회차의 실행은 계속 완료 처리할 수 있다. 보관된 회차는 수정하거나 실행 완료 상태를 바꿀 수 없고 복원한 뒤 다시 운영한다.
- 탐색 화면은 별도 검색 API 없이 현재 선택한 시즌의 `decisions`, `handoffItems`, `resources`를 통합한다. 결정은 제목·이유·대안·작성자·관련 역할, 바통은 내용·분류·역할, 자료는 제목·설명·역할을 검색하며 종류·역할·활성/보관 상태와 시즌 시간대 기준 기간으로 좁힌다. 생성 시각이 알려진 최신 기록부터 표시하고 활성 결과는 원본 화면으로 이동하며, 원본 확인 뒤 돌아와도 검색 조건을 유지한다. 보관한 자료는 보관 기록으로 검색하지만 활성 역할 자료 화면과 동작 대상으로는 표시하지 않는다. V14 이전 바통 항목과 역할 자료는 실제 생성 시각을 복원할 수 없어 `createdAt`이 `null`이고, 기간 필터가 없으면 시각 미상으로 뒤에 표시하며 기간 필터에서는 안내와 함께 제외한다.
- 열린 워크스페이스는 전경에서 10초마다 자동 동기화하고 창 포커스·네트워크 복구 시 다시 조회한다. 마지막 화면 갱신 시각과 수동 새로고침을 제공하며, 일시적인 재조회가 실패하면 기존 내용을 유지한 채 동기화 실패를 알린다. 접근 키가 폐기된 `403`은 기존 내용을 계속 편집할 수 있는 것처럼 표시하지 않고 접근 오류 화면으로 전환한다.
- 공용 API 클라이언트는 서버 연결 실패, 요청 시간 초과와 해석할 수 없는 성공 응답을 구분해 행동 가능한 한국어 안내로 수렴한다. 서버의 커넥션 획득·행 잠금·쿼리에 전파되는 트랜잭션 시간 예산은 클라이언트의 10초 시간 초과보다 짧은 순서로 두어, 클라이언트가 결과를 포기한 뒤 변경이 늦게 반영될 가능성을 줄인다. 서버가 5xx 오류와 함께 반환한 요청 ID는 같은 ID가 기록된 Spring 또는 Caddy 로그를 찾을 수 있도록 사용자 안내에 포함한다. 서버 처리 결과를 확정하지 못한 이 오류에서는 워크스페이스·콘텐츠 생성과 키 변경의 완료 전 멱등 저널을 보존해 같은 멱등 요청으로 다시 확인한다.
- 공유 콘텐츠 변경에서 `409 WORKSPACE_CONTENT_CONFLICT`를 받으면 편집 창을 닫고 최신 워크스페이스 프로젝션을 다시 조회한다. 이 조회가 진행 중이거나 실패한 동안에는 기존 기록의 수정·보관·완료 변경을 막고 수동 재시도를 제공하며, 조회 성공 뒤 최신 화면에서 사용자가 변경 의도를 다시 선택하게 한다.
- 구성원·역할·자료·루틴·회차·결정·바통 항목·시즌 정보·자동 회차 설정의 수정 충돌에서는 제출한 입력 한 건을 읽기 전용 초안으로 보존한다. 사용자는 초안을 복사하거나 버릴 수 있지만 자동 병합·재제출은 제공하지 않는다. 가장 최근 충돌의 초안만 화면 메모리에 남기며 브라우저 저장소에는 기록하지 않는다. 새 충돌, 새로고침, 계정·팀·시즌·접근 키 변경이나 접근 권한 상실 시 폐기한다. 세션 조회 실패는 계정 변경이나 권한 상실로 판단하지 않으며, 같은 계정으로 조회가 복구돼도 초안을 유지한다. 완료·보관 상태 변경과 역할 바통 상태 전이는 입력 초안을 만들지 않는다.
- 공용 대화상자와 작은 화면의 역할 상세 서랍형 패널은 처음 열릴 때 초점을 내부로 옮겨 순환시키고, `Escape`로 닫은 뒤 진입한 컨트롤로 돌려보낸다. 닫힌 서랍형 패널은 키보드와 화면 읽기 도구의 접근을 막으며, 바통의 역할 탭은 좌우 방향키와 `Home`·`End`로 이동하고 선택한 탭 패널과 연결된다.
- 작은 보조 문구·자리표시자·경고는 일반 크기 텍스트 기준 최소 `4.5:1`, 키보드 초점 표시는 밝은 본문과 어두운 탐색 영역에서 최소 `3:1`의 색 대비를 유지한다. 보관함 요약, 바통 탭 패널과 시각적으로 감춘 확인란도 초점 위치를 화면에 표시한다.
- 로딩, 오류, 빈 상태, 중복 제출 방지와 모바일 레이아웃을 제공한다.
- 서버 검증이 끝난 접근 키만 저장하고, 최근 워크스페이스 최대 5개를 다시 열거나 목록에서 지울 수 있다.
- 서버 제품 데이터의 권위 있는 복제본은 브라우저 `localStorage`에 저장하지 않는다. 로컬에는 접근 키, 최근 목록용 이름·식별자·시각과 완료 전 워크스페이스·콘텐츠·다음 시즌 생성 및 키 회전 요청의 멱등 정보만 보관한다. 워크스페이스 생성은 정규화된 요청별로 최대 5개, 구성원·역할·루틴·회차·결정·바통 항목·역할 자료·역할 바통 준비는 모든 작업 공간의 미완료 요청을 합쳐 최대 20개까지 작업 공간과 작업 종류별로 구분해 보관한다. 다음 시즌 생성 멱등 저널과 Web Lock은 팀 범위에서 하나의 미완료 전환만 허용한다.
- 온보딩은 완료 여부를 확인하지 못한 워크스페이스 생성 요청의 팀·시즌·기간·구성원 수와 기록 시각을 복구 목록으로 보여 준다. 사용자는 저장된 입력을 불러와 같은 멱등 키로 생성 결과를 확인하며, 기존 공유 링크 등으로 결과를 별도로 확인한 요청만 경고를 거쳐 개별적으로 폐기할 수 있다. 자동 만료와 일괄 폐기는 제공하지 않고, 다른 탭에서 생성 결과를 확인 중인 복구 기록의 폐기는 막는다. 선택한 복구 기록이 다른 탭에서 사라지거나 페이로드·기록 시각이 바뀌거나 신규 생성 초안이 다른 탭의 요청과 경합해 전송되지 않아도 같은 입력을 새 요청으로 자동 전환하지 않으며, 동일한 전체 스냅샷이 확인되면 그 멱등 키에 결속한다. 그 밖에는 사용자가 기존 결과를 확인한 뒤 명시적으로 전환해야 새 멱등 키를 발급한다. 탭 사이의 생성 요청을 안전하게 직렬화할 수 없는 브라우저에서는 신규 생성·결과 확인·복구 기록 폐기를 차단한다.
- 접근 키 변경은 같은 팀의 다른 탭과 멱등 저널 조회·생성부터 서버 결과 분류와 검증 정리까지 하나의 Web Lock 임계 구역에서 처리한다. 경쟁한 탭은 새 멱등 저널이나 POST 요청을 만들지 않고 먼저 시작한 탭의 완료를 안내하며, 이 직렬화를 지원하지 않는 브라우저에서는 회전을 시작하지 않는다.
- 콘텐츠 생성과 키 관리 화면의 접근 키 회전은 완료 전 멱등 정보를 내구 저장할 수 없으면 요청을 차단한다. 콘텐츠 생성은 같은 브라우저의 탭 사이에서 요청 결과가 확정될 때까지 한 번에 하나씩 처리하고, 다른 탭의 생성이 진행 중이면 새 요청을 전송하지 않는다. 이 직렬화를 지원하지 않는 브라우저에서도 콘텐츠 생성을 시작하지 않는다. 콘텐츠 생성이나 접근 키 회전 요청이 진행되는 동안에는 해당 대화상자의 다른 동작과 닫기·`Escape`·배경 닫기를 막아 같은 의도를 별도 UI 세션에서 중복 제출하지 않게 한다. 서버 반영 뒤 응답만 유실되면 저장한 동일 멱등 요청으로 생성된 리소스나 새 키를 회수한다. 워크스페이스·콘텐츠 생성과 키 회전 멱등 저널은 오류를 같은 요청 재확인, 새 요청 가능, 기존 결과 확인 후 새 요청 가능으로 구분하고, 결정적 종료나 성공 뒤에는 대상 스냅샷 삭제를 시도한다. Web Storage의 `setItem`과 `removeItem`이 예외 없이 끝나면 표준 API 계약에 따라 성공으로 간주하며 쓰기 후 읽기 검증이나 `null` 삭제 표식을 별도로 만들지 않는다. 저장소가 예외를 던져 완료 기록 정리가 필요하면 새로고침이나 작업 종류 전환 뒤에도 그 상태를 유지하고, 입력 양식 검증과 독립된 명시적 정리 동작을 제공하며, 정리가 성공하기 전에는 모든 콘텐츠 생성의 새 멱등 키 발급과 전송을 차단한다. 복구 결과가 만료되어 기존 리소스가 이미 생겼을 수 있는 경우에는 기록 정리 뒤에도 사용자가 기존 결과를 확인하고 명시적으로 재시도해야 새 멱등 키를 발급한다.
- 콘텐츠 생성 대기 기록은 POST 전에 `requestGuard`를 Web Lock 임계 구역에서 내구 저장한다. 결과 미확정 보호 기록이 하나라도 남으면 전역에서 가장 오래된 보호 기록의 같은 팀·시즌·작업 종류·정규화한 페이로드만 동일 멱등 키로 재확인하고, 그 밖의 모든 콘텐츠 새 멱등 키 발급과 전송은 차단한다. `cleanupRequired`가 남은 요청은 보호 기록 재확인보다 완료 기록 정리를 우선하며, 결과 미확정 보호 기록만 있는 항목은 자동으로 삭제하지 않는다.

백엔드는 팀·시즌·구성원·역할·역할 자료·루틴 정의·운영 회차·루틴 실행·결정·바통 항목·역할 바통의 MySQL 영속 모델, Flyway 마이그레이션과 `/api/v1` 파일럿 계약을 제공한다. 애플리케이션 경계에서 공유 키, 워크스페이스·구성원을 포함한 콘텐츠 생성과 키 변경의 멱등성, 역할·자료·루틴·회차·실행·결정·바통의 소속과 불변식, 분리된 생성 게이트와 운영자 복구 권한을 검증한다. 역할 바통은 역할과 분리한 이력 애그리거트로 `PREPARING → TRANSFERRED → ACCEPTED` 또는 `CANCELLED` 상태를 보존한다. 준비 시 두 담당자와 다음 담당 기간을 고정하고, 전달 시 활성·미완료 바통 항목 수와 자료 수를 스냅샷하며 누락 위험을 명시적으로 확인하게 한다. 수락은 역할의 현재·다음 담당자와 담당 기간을 원자적으로 전환하고, 역할마다 열린 바통은 하나만 허용한다. 전달 뒤에는 역할·바통 항목·자료 변경을 수락 또는 취소 전까지 막고, 열린 바통은 시즌 종료와 다음 시즌 시작도 막는다. 구성원은 팀에 속하지만 추가 요청의 시즌 경로는 접근 검증과 멱등 범위를 정하는 문맥으로 사용하며, 활동 상태와 관계없이 이름을 팀 안에서 유일하게 유지한다. 역할은 시즌별 스냅샷이고 같은 이름도 다른 시즌에는 사용할 수 있다. 다음 시즌 전환은 선택한 역할과 활성 루틴 정의만 새 UUID로 복사하고 계보와 시즌 시간대를 이어 받으며 담당자·기간을 초기화한다. 회차 일정, 회차·실행, 보관 루틴 정의, 결정·바통 항목·역할 바통 이력·자료는 복사하지 않아 원본 시즌의 기록으로 남는다. 활동 종료는 기존 역할·결정과 역할 바통 참여자 참조를 보존하는 가역 상태 변경이고, 새 역할 담당자·결정 작성자·역할 바통 참여자에는 활동 중 구성원만 배정한다. 자료 URL은 사용자 정보가 없는 `http` 또는 `https` 전체 주소만 허용하고 서버가 링크 대상을 조회하거나 신뢰성을 판정하지 않는다. 회차 생성은 현재 활성 루틴 정의와 실제 마감 규칙 전체를 실행 기록과 UTC `deadlineAt`으로 한 번만 복사한다. 정의를 추가·수정·보관·복원해도 이미 만든 회차의 실행은 바뀌지 않고 다음 회차부터 반영된다. 수동 회차 이름·날짜 수정과 모든 회차의 보관·복원은 기존 실행 식별자·스냅샷·상태를 바꾸지 않으며, 수동 날짜 정정 때만 복사된 규칙으로 실제 마감을 다시 계산한다. 보관된 회차 이름과 자동 회차의 원래 발생일은 계속 예약된다. 자동 생성기는 기본 1분 간격으로 데이터베이스 상태를 확인하고 한 실행 주기에서 모든 활성 시즌 후보와 시즌별 최대 8개 발생을 `Team` 공유 잠금 뒤 `Season` 배타 잠금으로 처리한다. 발생일 유일 제약과 전진 커서로 재실행에도 같은 자동 회차를 중복 생성하지 않는다. 처리 시점에 활성 루틴이 없으면 해당 발생일의 커서만 전진시키고 실행이 없는 자동 회차는 저장하지 않는다. 콘텐츠 생성은 멱등 예약과 리소스 저장을 한 트랜잭션으로 처리하고, 접근 키 변경과 구성원·시즌·역할·역할 자료·루틴 정의·시즌 회차·회차 실행·결정·바통 항목·역할 바통의 겹친 수정은 낙관적 잠금으로 조용한 덮어쓰기를 막는다. 일반 변경은 `Team → Season` 공유 잠금 아래 종료 여부를 확인하고 시즌 종료·전환은 같은 순서의 배타 잠금으로 직렬화한다. 구성원 활동 종료와 새 역할·결정·역할 바통 참여자 배정, 회차 보관과 실행 완료, 역할 바통 상태와 자식 바통 항목·자료 변경은 각 부모 행의 잠금을 공유해 검증 뒤 상태 변경이 끼어들지 않게 한다. 루틴 정의 보관·복원은 `Season` 배타 잠금으로 수동·자동 회차 생성 및 일반 루틴 변경과 직렬화한다. 실제 행 잠금 대기가 제한을 넘으면 접근 키 또는 콘텐츠 충돌로 끝내고, 일반 쿼리·트랜잭션·커넥션 시간 초과는 도메인 충돌로 오분류하지 않는다. 구성원 활동 종료와 시즌 종료는 각각 UTC `deactivatedAt`, `endedAt`을 기록하고 루틴 정의·회차·결정·바통 항목의 보관은 UTC `archivedAt`을 기록하는 가역 상태 변경이며 영구 삭제가 아니다. 기존 `routines.status`는 `회차 도입 이전 기록` 회차의 실행 상태로 이관하며 실제 과거 날짜를 알 수 없어 해당 회차의 날짜는 운영자가 실제 날짜로 정정할 때까지 비어 있다. 기존 기한 문구에서는 실제 마감을 복원할 수 없어 구조화된 마감은 비어 있으며 해당 실행은 `UNSCHEDULED`로 표시한다. 프로덕션 파일럿은 동일 출처 HTTPS와 내부 전용 MySQL, 모든 기존 공유 키를 강제 폐기하고 팀별 최신 대표 시즌 재발급 대상을 남기는 백업·복구 스크립트를 제공한다. 공급자 중립 `Account`·신원, 이메일 검증 아웃박스, 동일 출처 세션, 워크스페이스 구성원 관리의 기존 구성원 멤버십 연결·현재 상태 조회와 ROUND 참여권 발급 기반도 제공한다. 역할 자료 화면에서는 서버가 관리하는 ROUND 방 매핑을 생성하고 입장하거나 종료할 수 있다. 한 계정의 다중 팀 탐색, 초대·세부 권한과 외부 알림 채널은 아직 구현하지 않았다.

BATON 본체가 링크 대상을 조회하지 않는다는 원칙은 계속 유지한다. 채택된 WATCH 연동을 켠 환경에서는 BATON이 감시 적격 역할 자료의 목표 스냅샷을 같은 MySQL 트랜잭션의 아웃박스에 기록하고, 별도 서비스인 WATCH가 커밋 이후 공개 URL의 제한된 도달 가능성만 비동기로 점검한다. WATCH는 상태 변경 이벤트를 최소 한 번 전달 방식으로 직접 HTTPS 전달하고 BATON은 별도 Bearer로 보호한 `/api/v1/internal/resource-health-events`에서 이벤트 ID별 불변 인박스에 원자적으로 저장한다. 동일 재전송은 최초 접수증을 반환하고 같은 이벤트 ID의 다른 이벤트 봉투는 거부하며, 서로 다른 이벤트는 소스 리비전과 도착 순서에 관계없이 모두 보존한다. 인박스는 `RoleResource` 존재 조회나 FK에 의존하지 않는다. WATCH 결과는 자료의 존재·권한·신뢰성을 바꾸지 않는 비권위 상태이며 상태 프로젝션·UI와 인박스 보존 정책은 아직 구현하지 않았다. 저장소 구현만으로 실제 공개 WATCH→BATON 전달과 운영 활성화를 완료했다고 보지 않는다.

## 8. 첫 파일럿

사용자가 참여하는 그룹 스터디를 첫 운영 현장으로 삼는다.

- 실제 스터디의 시즌과 역할을 등록한다.
- 공유 링크를 파일럿 구성원에게 전달하고 같은 기록이 각 브라우저에서 보이는지 확인한다.
- 실제 HTTPS 주소를 서로 다른 두 기기에서 열어 공유 링크와 변경 동기화를 확인한다.
- 매 회차 전·중·후 루틴을 BATON에서 확인한다.
- 실제 운영에서 중단한 루틴 정의를 보관해 과거 회차 실행과 완료 상태가 남는지 확인하고, 복원한 정의가 새 회차부터 다시 포함되는지 확인한다. 모든 정의를 보관한 동안에는 빈 자동 회차가 생기지 않고 운영 화면이 활성 루틴 대기 상태를 설명하는지도 확인한다.
- 운영 방식이 바뀔 때 이유와 대안을 남긴다.
- 과거 결정 한 건의 결과·이유·관련 역할을 별도 설명 없이 탐색 화면에서 다시 찾는다.
- 역할 교대 전에 현재 담당자가 바통을 전달하고 실제 다음 담당자가 내용을 확인해 수락한다.
- 별도 설명 없이도 다음 행동을 찾을 수 있는지 관찰한다.
- 실제 기록을 넣기 전에 백업을 만들고 별도 환경에서 한 번 복구한다.
- 복구 리허설에서 이전 공유 링크가 거부되고 팀별로 재발급한 새 링크만 동작하는지 확인한다.

파일럿에서는 기능 수보다 다음 신호를 우선 확인한다.

- 담당자가 없어 빠지는 책임을 더 일찍 발견하는가
- 반복 운영을 준비하는 시간이 줄어드는가
- 과거 결정의 이유를 다시 찾을 수 있는가
- 다음 담당자가 질문해야 하는 양과 시행착오가 줄어드는가

## 9. 초기 비목표

- 메신저나 화상 회의를 대체하는 자체 채팅
- 급여, 인사평가, 성적과 학사 행정 전체를 다루는 ERP
- 범용 문서 편집기나 파일 저장소 대체
- 복잡한 전자결재와 회계
- 모든 프로젝트 관리 기능을 한 번에 제공하는 것
- AI가 사람을 대신해 조직의 결정을 내리는 것

외부 문서, 캘린더와 메시징 연동은 핵심 흐름이 검증된 뒤 검토한다.

## 10. 미결정 사항

다음 항목은 이 기준선에서 확정하지 않는다.

- 조직 초대, 계정 비활성화·탈퇴·비밀번호 재설정과 단계 강화 신원 연결·병합
- 공유 워크스페이스 capability(권한 증표)를 대체할 팀·시즌·역할별 세부 권한과 감사 모델
- 파일럿 이후의 클라우드 공급자, 다중 호스트와 무중단 배포 방식
- 알림 채널과 WATCH 외 나머지 외부 서비스 연동
- 과금 방식
- 결정·바통 이외 도메인의 세부 상태 머신과 영구 삭제·보존 기간 정책

현재 백엔드는 명시한 `Account` 세션·ROUND·워크스페이스·WATCH 경로만 공개하고 그 밖의 요청을 거부한다. `Account` 세션, 워크스페이스 capability(권한 증표)와 WATCH Bearer는 서로 대체할 수 없는 별도 인증 경계다.
파일럿 공유 키는 최종 계정·권한 모델이 아니라 한정된 그룹에서 핵심 흐름을 검증하기 위한 임시 접근 방식이다.
