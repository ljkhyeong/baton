# PRD-0001: BATON 제품 명세

- 상태: 초기 기준선
- 작성일: 2026-07-20
- 대상: 웹 서비스 MVP와 실제 그룹 스터디 파일럿

## 1. 제품 정의

BATON은 팀 업무와 인수인계를 관리하는 도구다. 담당자가 바뀌어도 업무·결정·자료 기록을 유지한다.

스터디, 동아리, 학생회, 학교 위원회, 회사의 프로젝트 팀과 TF처럼 여러 사람이 함께 일하는 조직을 대상으로 한다. 역할별 업무와 담당자, 반복 업무, 결정 이유와 인수인계 자료를 관리한다.

## 2. 해결하려는 문제

작은 조직은 별도의 운영 시스템 없이 메신저, 문서, 캘린더와 개인 기억에 의존하기 쉽다. 이때 다음 문제가 반복된다.

- 업무 방법이 기록되지 않아 담당자가 바뀌면 일이 누락된다.
- 반복 업무의 순서와 기준이 매번 다시 논의된다.
- 결정 결과만 남고 이유와 검토했던 대안은 사라진다.
- 인수인계가 임기나 프로젝트 종료 직전에 한꺼번에 이루어진다.
- 담당자 변경 전에 인수인계할 업무 방법과 접근 권한을 파악하기 어렵다.

BATON은 역할과 담당자, 반복 업무, 결정 기록, 인수인계를 함께 관리한다.

## 3. 제품 원칙

### 담당자가 바뀌어도 역할과 기록을 유지한다

책임은 사람에게 직접 고정하지 않고 역할에 둔다. 사람은 정해진 기간 동안 역할을 맡는다. 담당자가 바뀌어도 역할의 목적, 책임, 기록은 유지되어야 한다.

### 반복 업무를 회차별로 관리한다

한 번의 할 일뿐 아니라 모임 전·중·후, 매주, 매월처럼 되풀이되는 운영을 한눈에 확인할 수 있어야 한다.

### 결과와 함께 이유를 남긴다

결정에는 무엇을 정했는지뿐 아니라 이유, 검토한 대안, 영향을 받는 역할을 함께 남긴다.

### 인수인계는 마지막 날의 문서 작업이 아니다

역할을 수행하는 동안 담당 업무, 반복 업무, 결정, 자료와 주의사항을 기록하고 필요할 때 인수인계 문서로 정리해야 한다.

### 스터디에서 시작해 더 큰 조직으로 확장한다

첫 실제 사용처는 사용자가 참여하는 그룹 스터디다. 다만 제품 모델은 학교와 회사에도 적용할 수 있도록 조직 종류에 종속되지 않는 용어와 경계를 사용한다.

## 4. 핵심 개념

화면에서는 `반복 업무`, `인수인계`, `인수인계 문서`, `로그인 방법`을 공통 용어로 사용한다. API 필드명·열거형·기존 저장 데이터는 문구 변경과 관계없이 유지한다. 오늘 화면의 미완료 수는 선택한 회차의 미완료 업무 수이며, 인수인계 문서의 체크리스트 완료율은 보관하지 않은 항목 중 완료한 항목의 비율이다.

화면은 흰 배경과 얇은 구분선을 사용하고, 주요 동작은 짙은 버튼으로 표시한다. 데스크톱에는 왼쪽 메뉴와 상단의 팀·시즌 위치, 기록 검색, 갱신 상태를 고정된 위치에 배치한다. 화면 구성은 [Jira의 탐색 구조](https://www.atlassian.com/software/jira/guides/navigation/overview)와 [Notion의 사이드바](https://www.notion.com/help/navigate-with-the-sidebar)를 참고한다. 브랜드 아이콘은 릴레이 바통 모양의 주황색 SVG이며 앱과 브라우저 아이콘에 같은 파일을 사용한다.

오늘 화면은 남은 업무 수, 업무 추가, 회차 선택과 완료 체크에 집중한다. 업무는 지연된 순서로 표시하며 업무명·상태와 마감·담당자를 열로 구분한다. 모바일에서는 상태와 마감을 업무명 아래에 표시한다. 담당자를 누르면 역할 화면의 상세를 연다. ‘조치할 항목’은 조치가 필요할 때만 표시하며, 자료 재확인과 내 담당 업무는 ‘내 업무와 확인할 자료’에서 펼친다. 회차 생성·수정은 일정, 결정 작성·조회는 기록에서 제공한다. 결정 기록과 검색 결과는 장식용 번호나 연결선 없이 내용과 구분선으로 정리한다. 주간 업무 점검과 캘린더 연결도 기본으로 접어두되, 특정 주간 점검 링크로 들어오면 해당 내용을 바로 연다. 모바일에서는 하단 메뉴를 사용하고 주요 버튼과 업무 완료·담당자 조작 영역을 44px 이상으로 제공한다.

모바일 상단에서는 팀·시즌 이름과 공유·관리 버튼을 두 줄로 구분한다. 역할 목록에는 현재 담당자와 다음 담당자를 함께 표시한다. 인수인계는 짧은 진행 요약 다음에 준비·전달·수락 버튼과 체크리스트를 배치한다. 시작 화면의 소개는 짧게 유지하고, 최초 진입 때 입력칸으로 자동 이동하지 않는다.

검색 화면은 시즌 선택과 검색어를 먼저 표시하고 종류·역할·상태·작성일은 ‘상세 필터’에서 펼친다. 접어도 검색 조건은 유지하며 적용 중인 필터 개수를 표시한다. 원본 기록을 보고 검색으로 돌아왔을 때 상세 필터가 적용되어 있으면 펼쳐서 보여준다.

기한 입력은 안내용인 ‘기한 설명’과 지연 판정에 사용하는 ‘마감 기준일·마감 시각’으로 구분한다.
요청 복구 화면의 ‘임시 기록 삭제’는 브라우저에 남은 재시도 정보만 삭제한다.
검색의 보관 여부는 ‘전체 기록’, ‘보관하지 않은 기록’, ‘보관 기록’으로 표시한다. 날짜 필터는 기록 작성일을 기준으로 하며 ‘작성일(시작)·작성일(종료)’로 표시한다.

역할 상세의 ‘담당 반복 업무’는 해당 역할이 맡은 업무이며 시간상 다음 업무를 뜻하지 않는다. 수락 대기 항목은 ‘수락할 인수인계’, 보관함의 개별 항목은 ‘보관한 체크리스트 항목’으로 표시한다. 자료 등록은 ‘자료 추가’, 기존 자료 재사용은 ‘현재 시즌에 추가’, 계정과 팀 구성원 연결은 ‘내 이름 선택’으로 표시한다. 회차 생성 설정은 ‘회차 자동 생성’, 미리 생성할 일수는 ‘회차 생성 시점’으로 표시한다.


기록 검색의 상태는 `전체 기록`, `보관 안 함`, `보관됨`으로 표시한다. 인수인계의 `체크리스트 항목` 수는 보관한 항목을 제외하며, 전달 후에는 전달 당시 개수를 표시한다. 화면에서 로그인 세션 종료는 `로그아웃`으로 안내한다. 계정 비활성화는 로그인·팀 접근을 중지하는 기능이며 기록을 삭제하지 않는다는 점을 함께 설명한다.

역할 입력과 상세 화면, 인수인계 문서에서는 `역할 목적`, `담당 업무`, `주의사항`을 사용한다. 인수인계 항목의 상태는 `완료`와 `미완료`로 표시한다. `임시 기록 삭제 재시도`는 브라우저에 남은 요청 정보를 삭제하는 동작으로 안내하며, 서버의 업무 기록이나 작성 중인 본문 초안을 지우는 동작과 구분한다.

## 5. 핵심 사용자 경험

### 오늘

사용자는 현재 시즌의 시간대를 기준으로 예정·진행·지연·완료 상태의 반복 업무와 담당자 공백·업무 지연을 확인한다. 조치할 항목에는 판정 이유와 다음 행동을 함께 표시한다.

로그인 계정과 활동 중인 팀 구성원이 연결되어 있으면 `내 담당 업무`에서 현재 담당 역할의 미완료 반복 업무 실행과 자신에게 전달된 수락 대기 인수인계를 모아 본다. 보관된 회차와 완료 실행은 제외하고 회차 선택과 관계없이 현재 시즌 전체에서 찾으며, 마감순으로 정렬한다. 반복 업무는 해당 회차의 일정 화면으로, 인수인계는 해당 역할의 전달 내용으로 이동한다. 이동한 반복 업무 또는 인수인계 본문을 화면에 표시하고 키보드 초점도 함께 옮긴다. 미연결·로그인 필요·활동 종료·조회 실패를 구분하며, 개인화 표시는 공유 키 접근 권한이나 담당자 확인 계약을 바꾸지 않는다.

`주간 업무 점검`을 펼치면 로그인 계정과 활동 중인 팀 구성원 연결을 확인한 뒤 BRIEF의 최신
불변 요약을 조회한다. 사용자는 이번 주 요약 생성을 요청하고 생성 당시 주차·시각·신호 종류와
상태를 확인한다. 종료 시즌은 조회만 제공하며, 현재 운영 상태와 과거 요약을 구분한다.
서비스 연결·오류·재조회와 데이터 표시 범위는 [PRD-0008](../0008_brief-edition-query-and-generation/spec.md)이 소유한다.

### 역할

팀이 지속해서 필요로 하는 역할을 만들고 목적, 책임, 현재 담당 기간과 다음 담당자를 확인한다. 다음 시즌으로 이어 온 역할은 상세에서 `이전 시즌 기록 보기`를 펼쳐 당시 목적·책임·주의사항, 자료, 결정과 이유, 인수인계 항목을 조회한다. 현재 시즌은 그대로 유지하며 펼칠 때만 이전 시즌을 조회한다. 연결된 이전 시즌이나 역할이 없는 기존 이관 기록에서는 이 기능을 표시하지 않는다. 조회 실패 시 오류와 재시도를 제공하고 다른 역할의 자료로 대체하지 않는다. 필요한 자료만 골라 제목·링크·설명을 확인하면 현재 역할에 새 자료로 연결한다. 원본 기록은 유지하며, 종료 시즌과 전달 후 수락 대기 역할에서는 자료 추가를 막는다.

### 일정

모임 또는 업무의 전·중·후에 반복되는 반복 업무를 역할과 실제 마감에 연결하고 이번 회차의 진행 상황을 확인한다. 시즌의 주간·격주 일정을 켜 반복 회차를 자동으로 만들거나 필요할 때 수동 회차를 만든다. 더 이상 반복하지 않는 반복 업무 정의는 과거 회차의 실행 기록을 유지한 채 보관했다가 복원한다. 수동·자동 회차의 이름·날짜는 실행 기록을 유지한 채 정정한다. 자동 회차는 이번 회차만 건너뛰었다가 복원할 수 있으며 원래 발생일과 다음 반복 일정을 유지한다.

### 기록

중요한 결정을 이유와 대안까지 기록하고 관련 역할에서 다시 찾는다. 잘못 입력한 기록은 정정하고, 당장 사용하지 않는 기록은 삭제하지 않고 보관했다가 복원한다.

### 검색

현재 선택한 시즌의 결정, 인수인계 항목과 역할 자료를 하나의 시간 흐름에서 검색하고 기록 종류·관련 역할·활성/보관 상태·기간으로 좁힌다. 종료 시즌을 포함한 모든 시즌을 선택해 함께 탐색할 수 있다.

### 인수인계

역할별 인수인계 준비 상태를 확인하고 책임, 반복 업무, 결정, 자료, 조언과 남은 작업을 인수인계 문서로 정리한다. 인수인계 항목도 운영 중 정정하고 보관·복원할 수 있다. 현재 담당자는 다음 담당자와 새 담당 기간을 지정해 인수인계를 준비하고, 미완료 항목·자료 누락 경고를 확인한 뒤 전달한다. 다음 담당자가 수락하면 역할의 현재 담당자와 담당 기간이 함께 바뀌며, 수락 전에는 현재 담당자가 취소할 수 있다.

인수인계 문서 미리보기에는 역할의 목적·책임·주의사항과 활성 반복 업무·결정·자료, 보관하지 않은 모든 인수인계 항목을 담는다. 완료한 항목도 내용과 종류를 남기고 미완료 항목 수를 별도로 표시한다. 미리보기의 `인쇄 / PDF 저장` 버튼으로 인수인계 문서만 출력하거나 PDF로 저장할 수 있으며, 팀·시즌 이름과 자료 주소를 함께 출력한다. 이 버튼은 인쇄 호출 전에 주소의 접근 키를 제거하고 인쇄 종료·취소 뒤 복원해, 저장소가 막힌 환경에서도 다시 접속할 키를 잃지 않게 한다. 브라우저 메뉴·단축키 인쇄는 이 처리를 거치지 않으므로 키가 주소에 남아 있으면 반드시 미리보기 버튼을 사용하도록 안내한다. 출력물은 현재 조회한 기록의 사본이며 이후 변경을 자동 반영하지 않는다.

### 시즌

팀의 과거·현재 시즌을 전환해 조회하고, 운영 중인 시즌의 이름과 기간을 정정한다. 시즌을 명시적으로 종료하면 기록은 읽기 전용으로 보존한다. 다음 시즌을 시작할 때 이어 갈 역할과 활성 반복 업무 정의만 선택해 새 식별자로 복사하며 담당자·담당 기간과 실행 상태는 다시 정한다.

## 6. MVP 범위

- 팀과 기간이 있는 시즌을 만든다.
- 시즌의 이름·기간과 종료 상태를 관리하고 필요한 역할·반복 업무 정의를 다음 시즌으로 이어 간다.
- 구성원과 역할을 분리해 관리하고 역할 담당 기간을 기록한다.
- 역할의 목적, 책임과 반복 업무를 관리하고 사용하지 않는 반복 업무 정의를 실행 기록과 분리해 보관·복원한다.
- 시즌 시간대와 주간·격주 일정을 관리하고 반복 회차를 중복 없이 자동 생성한다.
- 반복 업무의 실제 마감과 이번 운영 회차의 예정·진행·지연·완료 여부를 확인한다.
- 결정 내용, 이유, 대안과 관련 역할을 기록한다.
- 결정의 결과·이유·대안, 인수인계 항목과 역할 자료를 역할과 시간 흐름으로 다시 찾는다.
- 역할에 자료와 주의사항을 기록한다.
- 역할별 인수인계 문서를 준비하고 현재 담당자의 전달과 다음 담당자의 수락으로 역할 담당자·기간을 전환한다.
- 스터디를 모바일과 데스크톱 웹에서 실제 운영할 수 있다.

알림 설정은 [API 계약](../0002_api-contract/spec.md), 팀 권한은 [팀 접근 계약](../0009_team-account-access/spec.md)을 따른다. 미구현 기능의 보존 기간·세부 상태는 파일럿 요구를 확인한 뒤 정한다.

### 파일럿 시작과 접근·복구 원칙

첫 파일럿은 팀·시즌 생성 → 역할·일정 등록 → 회차 업무 → 결정 기록 → 인수인계 순서로 진행한다.
빈 구성 또는 `STUDY_V1`(스터디)·`TEAM_V1`(팀 운영)·`TASK_FORCE_V1`(TF)을 선택할 수 있다. 템플릿은 역할 3개와 반복 업무 3개를
같은 트랜잭션으로 만들며 생성 전에 내용을 보여 준다. 담당자·담당 기간·마감·일정·회차는 직접 정한다.
템플릿의 담당자 공백도 업무 점검에 포함한다. 기능별 동작은 [현재 구현 상태](#7-현재-구현-상태)를 따른다.

공유 키 팀과 계정 권한 팀은 다음 기준으로 구분한다.

- 공유 키 팀은 링크를 아는 사람이 작업 공간 전체를 읽고 쓸 수 있다. 계정 로그인만으로 이 권한을 대신하지 않는다.
- 공유 키는 URL 프래그먼트에 포함한다. 서버는 접근 키와 생성·키 변경의 멱등 키를 SHA-256 해시로 저장한다. 접근 키 원문은 최초 성공과 같은 요청의 응답 유실 복구 때만 반환한다.
- 계정 권한으로 전환한 팀은 기존 공유 키를 거부하고 관리자·구성원·열람자 권한을 적용한다. 전환은 [PRD-0009](../0009_team-account-access/spec.md)를 따른다.
- 공유 키 팀의 `confirmedByMemberId`는 담당자 명의의 확인 선언이다. 실제 로그인 사용자를 인증한 감사 기록으로 사용하지 않는다.

작업 공간의 `공유` 버튼은 지원 브라우저에서 기기의 공유 창을 연다. 미지원·권한 차단 등으로 공유할 수 없으면 링크를 복사하고, 복사도 차단되면 직접 복사할 주소를 보여 준다. 사용자가 취소하거나 공유 대상 앱이 없으면 아무 작업도 하지 않는다. `현재 링크 복사` 버튼은 기기 공유 창을 열지 않고 링크만 복사한다. 공유 방식이 달라져도 위 접근 권한은 그대로 적용한다.

키 유출·분실과 백업 복구는 다음 순서를 따른다.

- 유출된 키는 변경하고 새 링크를 전달한다. 모두 키를 잃었다면 생성 키와 분리된 운영자 복구 키로 재발급한다. 이후 키가 바뀌면 과거 멱등 요청으로 폐기한 키를 되살릴 수 없다.
- 백업 복원 후 서버를 공개하기 전에 모든 팀의 과거 공유 키를 무효화한다. 팀별로 새 멱등 키를 사용해 접근 키를 발급한다. 계정 권한 팀은 자동 복원 완료를 지원하지 않으며 격리 환경에서 권한을 대조한다. [남은 운영 작업](../../../HANDOFF.md#팀-권한-전환복원)
- 잘못된 공유 키는 브라우저에 저장된 정상 키를 덮어쓰지 않는다. 키를 저장할 수 없으면 원래 공유 링크 탭을 유지하고 로그인을 새 탭에서 진행한다. 로그인 복귀 주소에 키를 복제하지 않는다.

### 남은 제품 범위

- 제품 기록의 영구 삭제와 계정 완전 탈퇴·직접 재활성화
- 역할별 세부 권한, 아직 지원하지 않는 기록의 편집 이력
- 추가 신원 확인을 거친 로그인 수단 연결·계정 병합
- 마감·지연의 외부 메시징·메일 알림

팀 전환·초대·계정 비활성화와 CAL 일정 전달은 구현되어 있다. 운영 활성화·실제 기기 검증은 기능별로 남아 있다.

## 7. 현재 구현 상태

팀·시즌·구성원을 등록하면 서버에 저장되는 작업 공간을 만든다. 아래 기능은 구현되어 있으며 실제 운영 환경에서 확인할 항목은 [HANDOFF](../../../HANDOFF.md)에 남긴다.

### 계정과 팀 접근

- Google·Naver·자체 이메일 로그인과 동일 출처 서버 세션·CSRF를 사용한다. 인증 토큰을 브라우저 저장소에 따로 보관하지 않는다.
- 공유 키 팀은 ‘내 이름 선택’에서 로그인 계정을 활동 중인 구성원 한 명과 연결한다. 연결은 활동 종료 후에도 남으며 로그인 복귀 주소에 공유 키를 복제하지 않는다. 계정 권한 팀의 초대·권한은 [팀 접근 계약](../0009_team-account-access/spec.md)을 따른다.
- 자체 이메일 계정은 30분짜리 일회용 링크로 비밀번호를 재설정한다. 계정 존재 여부는 접수 응답에 드러내지 않는다. 재설정 후 기존 세션은 다음 요청에서 거부하며 다시 로그인해야 한다. 실제 SMTP 검증 후 가입과 별도로 활성화한다.
- `/account`에서 이름·로그인 방법, 비밀번호 변경, 모든 기기 로그아웃과 내 캘린더 구독을 관리한다. 비밀번호 변경·세션 종료는 공유 키나 이미 발급된 ROUND 참여권을 폐기하지 않는다. 팀 권한을 잃어도 본인 구독을 관리할 수 있으며 구독 주소는 다시 노출하지 않는다.

상세 인증 동작은 [PRD-0005](../0005_account-and-round-authentication/spec.md), 캘린더 구독은 [PRD-0006](../0006_calendar-integration-contract/spec.md)을 따른다.

오늘 화면의 ‘내 캘린더에 추가’에서 구독 주소를 발급하고 Google·Apple·Outlook 등록 절차를 확인한다. 앱 등록 여부는 확인하지 않으며 일정 반영에는 앱별 갱신 시간이 걸린다.

### 내 업무와 담당자 관리

- ‘내 팀’의 ‘모든 팀의 내 할 일’은 내가 맡은 미완료 반복 업무와 수락할 인수인계를 모은다. ‘전체·기한 지난 업무·마감 임박 업무·그 밖의 남은 업무·수락할 인수인계’로 좁히고 원본 회차나 인수인계로 이동한다. 마감 임박은 계정의 개인 알림 설정 시간을 기준으로 구분한다.
- 같은 화면은 종료하지 않은 시즌의 활성 결정·인수인계 항목·역할 자료 중 생성 시각이 확인되는 최근 5개를 함께 표시한다. 기록을 선택하면 해당 팀·시즌의 원본 화면을 연다. 수정·보관 시각을 최근 생성 시각으로 추측하지 않는다.
- 이 목록에는 계정 권한이 승인된 팀의 종료하지 않은 시즌만 포함한다. 공유 키 팀과 종료 시즌은 제외한다. 기존 작업 공간 API를 사용하며 전경에서 30초마다 갱신한다. 일부 조회 실패나 조회 사이에 바뀐 구성원 활동 상태는 누락으로 안내하고 해당 팀의 업무·최근 기록을 제외한다. 권한 거부가 확인된 팀은 캐시 데이터도 목록에서 제외하고 주기·창 포커스·네트워크 복구에 따른 재조회를 멈추며, ‘업무 새로고침’으로 다시 확인한다.
- 구성원 이름은 활동 여부와 관계없이 팀 안에서 고유해야 한다. 활동 종료 후에도 기존 역할·결정·인수인계 기록은 보존하며 새 담당자·작성자·인수인계 참여자로는 선택할 수 없다. 활동 재개를 지원한다.

### 반복 업무·회차·시즌

- 반복 업무의 내용·담당 역할·마감을 정하고 회차별로 완료 처리한다. 새 회차는 생성 당시 사용 중인 업무와 마감 규칙을 복사한다. 이후 정의를 수정·보관해도 기존 회차의 업무와 완료 상태는 바뀌지 않는다.
- 주간·격주 자동 생성과 수동 회차 생성을 지원한다. 활성 반복 업무가 없으면 빈 자동 회차를 만들지 않고 다음 발생일로 진행한다. 화면에는 반복 업무를 추가하거나 복원해야 한다고 안내한다.
- 회차의 이름·날짜를 수정하고 보관·복원할 수 있다. 날짜를 바꾸면 복사된 마감 규칙으로 마감을 다시 계산한다. 자동 회차는 원래 발생일을 보존하며 기존 현지 모임 시각을 새 날짜에 적용한다. 한 회차를 건너뛰어도 다음 반복 일정은 유지한다.
- 반복 업무 정의를 보관하면 새 회차에서 제외한다. 기존 회차의 실행은 계속 완료 처리할 수 있다. 회차 자체를 보관하면 수정·완료 변경을 막고 복원 후 다시 허용한다.
- 시즌의 이름·기간을 수정하고 종료·재개할 수 있다. 종료 시즌은 조회만 가능하며 일반 변경은 서버도 `SEASON_ENDED`로 거부한다.
- 다음 시즌에는 선택한 역할과 활성 반복 업무 정의만 새 UUID로 복사한다. 이전 역할 연결과 시간대는 이어받고 담당자·담당 기간은 초기화한다. 일정·회차·완료 상태·결정·자료·체크리스트·인수인계 이력은 원본 시즌에 남는다.
- 날짜·마감·진행률은 시즌의 IANA 시간대를 사용한다. 기본값은 `Asia/Seoul`이다. 진행률은 시작일 0%, 종료일 100%이며 다음 날부터 지난 시즌으로 안내한다. 하루짜리 시즌은 해당 날짜에 `1 / 1주`, 100%로 표시한다.

자동 생성의 잠금·중복 방지와 마감 계산은 [ADR-0012](../../ADR/0012_round_schedule_and_deadline_automation/adr.md), 시즌 전환은 [ADR-0011](../../ADR/0011_season_lifecycle/adr.md)을 따른다.

### 업무 점검과 인수인계

‘조치할 항목’은 현재 기록에서 발견한 문제와 필요한 행동을 표시한다.

| 점검 대상 | 기준 |
| --- | --- |
| 현재 담당자 | 담당자가 없거나 활동을 종료한 역할 |
| 다음 담당자·인수인계 시작 | 담당 종료일이 14일 이내이거나 지났는데 후임이 없거나 인수인계를 시작하지 않은 역할 |
| 인수인계 준비 | 주의사항이 있는 역할에 담당 업무·자료·체크리스트가 부족한 경우 |
| 반복 업무 지연 | 서로 다른 활성 회차에서 같은 업무가 2회 이상 지연된 경우 |
| 전달·수락 | 다음 담당 시작일이 7일 이내이거나 지났는데 전달·수락이 남았거나 담당 기간 사이에 공백이 있는 경우 |

현재 담당자와 같은 후임, 필요한 참여자의 활동 종료도 확인한다. 종료 시즌과 보관 회차·체크리스트 항목은 조치 대상에서 제외한다. 세부 판정과 중복 표시 방지는 [API 계약](../0002_api-contract/spec.md)을 따른다.

인수인계는 `PREPARING → TRANSFERRED → ACCEPTED` 또는 `CANCELLED` 이력으로 관리한다. 준비할 때 두 담당자와 다음 담당 기간을 정하고, 전달할 때 당시 체크리스트·자료 수와 누락 경고 확인을 저장한다. 수락하면 담당자와 담당 기간을 함께 변경한다.

역할마다 진행 중인 인수인계는 하나만 허용한다. 전달 후 수락·취소 전까지 역할·자료·체크리스트 변경을 막는다. 진행 중인 인수인계가 있으면 시즌 종료·다음 시즌 시작도 막는다. 상태별 권한과 확인자는 [ADR-0013](../../ADR/0013_role_handoff_lifecycle/adr.md)을 따른다.

### 기록·자료·검색

- 결정·자료·체크리스트 항목을 수정하고 보관·복원한다. 보관 자료는 일반 역할 화면, 인수인계 준비 자료 수, ROUND 방 동작과 WATCH 활성 감시 대상에서 제외한다. 보관함과 검색에서는 계속 조회한다.
- 검색은 현재 시즌 또는 요청 시 조회한 모든 시즌의 결정·체크리스트·자료를 통합한다. 별도 검색 API는 사용하지 않는다. 검색 대상은 결정의 제목·이유·대안·작성자·관련 역할, 체크리스트의 내용·분류·역할, 자료의 제목·설명·역할이다.
- 종류·역할·보관 여부·작성일로 좁히고 최신 기록부터 표시한다. V14 이전의 작성 시각 미상 기록은 날짜 필터가 없으면 뒤에 표시하며, 날짜 필터를 쓰면 안내 후 제외한다. 원본을 확인하고 돌아와도 검색 조건은 유지한다.
- 자료 URL은 사용자 정보가 없는 `http`·`https` 전체 주소만 허용한다. BATON 본체는 링크 내용을 직접 조회하거나 신뢰성을 판정하지 않는다. 사람의 자료 확인 기록과 WATCH 점검 결과는 구분한다.

### 화면 갱신과 수정 충돌

- 전경의 작업 공간은 10초마다 갱신하고 창 포커스·네트워크 복구 때 다시 조회한다. 마지막 갱신 시각과 수동 새로고침을 제공한다. 일시 실패에는 기존 내용을 유지하지만 접근 권한 거부는 접근 오류 화면으로 전환한다.
- 연결 실패·요청 시간 초과·해석할 수 없는 응답을 구분해 재시도 방법을 안내한다. 5xx 응답의 요청 ID는 운영자가 Spring·Caddy 로그를 찾는 데 사용한다. 서버 처리 제한은 브라우저의 10초 요청 제한보다 짧게 둔다. [ADR-0009](../../ADR/0009_server-request-time-budget/adr.md)
- `409 WORKSPACE_CONTENT_CONFLICT`가 발생하면 편집 창을 닫고 최신 데이터를 조회한다. 조회 성공 전에는 기존 기록의 수정·보관·완료 변경을 막는다.
- 입력 수정 충돌에서는 마지막 제출 한 건을 읽기 전용 초안으로 남긴다. 복사·폐기만 가능하며 자동 병합·재제출하지 않는다. 완료·보관·인수인계 상태 변경에는 초안을 만들지 않는다.
- 충돌 초안은 화면 메모리에만 남긴다. 새 충돌·새로고침·계정·팀·시즌·접근 키 변경·권한 상실 때 지운다. 세션 조회의 일시 실패와 같은 계정으로의 복구는 초안을 지우지 않는다.
- 대화상자와 모바일 역할 상세는 초점을 내부로 옮기고 순환시킨다. `Escape`로 닫으면 열기 버튼으로 초점을 돌려준다. 화면 크기로 역할 상세의 표시 방식이 바뀌면 초점을 열린 상세나 본문으로 옮긴다. 닫힌 상세는 키보드·화면 읽기 도구에서 제외한다. 역할 탭은 방향키·`Home`·`End`를 지원한다.
- 보조 문구·경고의 색 대비는 최소 `4.5:1`, 초점 표시는 최소 `3:1`을 유지한다. 로딩·오류·빈 결과와 중복 제출 방지를 제공한다.

### 브라우저 저장과 응답 유실 복구

업무 데이터의 원본은 서버에 둔다. 브라우저에는 검증된 공유 키, 최근 작업 공간 최대 5개, 미완료 요청 복구 정보와 [작성 중 본문 초안](#작성-중-본문-초안)을 저장한다. 초안은 현재 탭에만 보관한다.

| 복구 기록 | 저장 범위·한도 |
| --- | --- |
| 작업 공간 생성 | 브라우저에 미완료 요청 최대 5개 |
| 구성원·역할·업무·회차·결정·체크리스트·자료·인수인계 준비 생성 | 모든 작업 공간의 미완료 요청 합계 최대 20개 |
| 다음 시즌 생성 | 팀별 미완료 전환 1개 |
| 접근 키 변경 | 팀별로 요청 생성부터 결과 확인·정리까지 직렬 처리 |

생성·키 변경은 복구 정보를 저장한 뒤 전송한다. 같은 브라우저의 탭 간 요청은 Web Lock으로 직렬 처리한다. 저장이나 잠금이 지원되지 않으면 새 요청을 보내지 않고 복구 방법을 안내한다.

- 응답을 받지 못하면 같은 멱등 키와 입력으로 결과를 확인한다. 생성 확인 목록에는 팀·시즌·기간·구성원 수·템플릿·기록 시각을 표시한다.
- 다른 탭에서 확인 중인 기록은 지울 수 없다. 자동 만료·일괄 폐기도 제공하지 않는다. 기록이 사라지거나 입력·시각이 달라져도 자동으로 새 요청을 만들지 않는다. 같은 스냅샷이면 기존 키를 사용하고, 그 밖에는 기존 결과를 확인한 뒤 사용자가 다시 요청해야 한다.
- 콘텐츠 생성은 전송 전에 `requestGuard`를 저장한다. 결과 미확정 기록이 있으면 가장 오래된 기록과 같은 팀·시즌·종류·입력만 재확인할 수 있으며 다른 새 생성은 막는다.
- `cleanupRequired`가 있으면 결과 재확인보다 기록 삭제를 우선한다. 삭제 전에는 새 멱등 키 발급·전송을 막으며 새로고침·작업 전환 후에도 이 제한을 유지한다. 결과 미확정 기록을 자동 삭제하지 않는다.
- 성공하거나 같은 요청을 더 진행할 수 없는 오류가 확정되면 복구 기록 삭제를 시도한다. Web Storage가 예외 없이 완료되면 성공으로 처리한다. ‘임시 기록 삭제’는 이 브라우저 기록만 지우며 서버 업무와 완료 이력은 지우지 않는다.
- 생성·키 변경 중에는 대화상자의 다른 동작과 닫기·`Escape`·배경 닫기를 막는다. 화면을 떠난 뒤 늦게 온 응답은 현재 주소·접근 키를 덮어쓰지 않으며, 로그아웃으로 지운 키도 다시 저장하지 않는다. 이미 시작한 기록 삭제와 세션 조회는 완료하고 다시 진입했을 때 결과를 확인한다.

요청별 만료·오류 분류·복구 조건은 [API 계약](../0002_api-contract/spec.md)을 따른다.

### 백엔드와 외부 점검

백엔드는 MySQL 영속화·Flyway와 `/api/v1` 계약을 제공한다. 권한·소속·상태 변경·멱등 저장을 트랜잭션 안에서 검증하고, 동시 수정은 낙관적 잠금과 부모 행 잠금으로 보호한다. 잠금 순서·충돌·시간 초과는 [API 계약](../0002_api-contract/spec.md)과 기능별 ADR을 따른다.

기존 데이터 중 실제 회차 날짜·마감을 알 수 없는 값은 임의로 복원하지 않는다. V5 이전 업무 상태는 ‘회차 도입 이전 기록’으로 옮기고 날짜는 정정 전까지 비워 둔다. 구조화된 마감이 없는 실행은 `UNSCHEDULED`로 표시한다.

WATCH 연동은 자료 변경을 아웃박스에 저장하고 커밋 후 외부 서비스가 URL을 점검한다. 수신 이벤트는 별도 Bearer로 보호한 인박스에 저장하며 같은 ID·같은 내용은 중복 처리하지 않고 같은 ID·다른 내용은 거부한다. 서로 다른 이벤트는 도착 순서와 소스 리비전에 관계없이 보존하고 자료 존재 조회나 FK에 의존하지 않는다.

역할 상세는 별도 API로 자료 연결 상태·최근 실패 원인·연속 실패 횟수를 조회하고 재점검을 접수한다. 최근 연결 판정과 점검 시도를 구분하며 판정이 5분 이상 오래되면 확인 필요로 표시한다. 내부 오류로 시도 시각만 갱신돼도 이전 판정이 유효해지지는 않는다.

편집이 제한돼도 상태 조회는 유지한다. 오프라인·만료 캐시·조회 실패를 현재 정상 상태로 표시하지 않으며 점검 제외와 주소 반영 대기를 구분한다. 역할 이동 후 재점검 대기시간·접수·새 결과 안내는 유지하고 계정·팀·시즌·자료·URL·공유 키별로 구분한다. 수동 조회와 실제 상태 변경을 화면 읽기 도구에 알린다.

WATCH 결과는 자료의 존재·권한·신뢰성을 바꾸지 않는다. 공개 HTTPS 검증, 이벤트 기반 상태 저장과 인박스 보존 정책은 남아 있다. 상세 기준은 [WATCH 계약](../0004_watch-integration-contract/spec.md)과 [현재 상태 조회](../../ADR/0021_watch-current-state-query/adr.md)를 따른다.

### 주간 업무 점검과 요약

‘오늘’의 ‘주간 업무 점검’에서 현재 미해결 항목·이번 주 해결 항목과 변경 이력을 조회한다.
‘조치할 항목’과 BRIEF는 반영 시점이 다를 수 있으며 조회 실패와 빈 결과를 구분한다.
로그인·팀 접근 조건과 필터는 [PRD-0009](../0009_brief-current-attention/spec.md)를 따른다.

‘저장된 주간 요약’은 생성 당시 내용을 보존한다. 열린 시즌에서 전달 완료 후 이번 주 요약을 만들고,
과거 요약과 비교하거나 현재 업무로 이동할 수 있다. 비교에서 제외됐다는 이유만으로 문제가 해결됐다고
판단하지 않는다. 원본 식별자·변경 번호는 ‘연동 상세’에서 확인한다. 조회·생성은
[PRD-0008](../0008_brief-edition-query-and-generation/spec.md), 이력·비교·추가 전달 안내·공유·인쇄는
[PRD-0010](../0010_brief-navigation-and-readiness/spec.md)을 따른다.

## 8. 첫 파일럿

사용자가 참여하는 그룹 스터디를 첫 운영 현장으로 삼는다.

- 실제 스터디의 시즌과 역할을 등록한다.
- 공유 링크를 파일럿 구성원에게 전달하고 같은 기록이 각 브라우저에서 보이는지 확인한다.
- 실제 HTTPS 주소를 서로 다른 두 기기에서 열어 공유 링크와 변경 동기화를 확인한다.
- 매 회차 전·중·후 반복 업무를 BATON에서 확인한다.
- 실제 운영에서 중단한 반복 업무 정의를 보관해 과거 회차 실행과 완료 상태가 남는지 확인하고, 복원한 정의가 새 회차부터 다시 포함되는지 확인한다. 모든 정의를 보관한 동안에는 빈 자동 회차가 생기지 않고 일정 화면이 활성 반복 업무 대기 상태를 설명하는지도 확인한다.
- 운영 방식이 바뀔 때 이유와 대안을 남긴다.
- 과거 결정 한 건의 결과·이유·관련 역할을 별도 설명 없이 검색 화면에서 다시 찾는다.
- 역할 교대 전에 현재 담당자가 인수인계를 전달하고 실제 다음 담당자가 내용을 확인해 수락한다.
- 별도 설명 없이도 다음 행동을 찾을 수 있는지 관찰한다.
- 실제 기록을 넣기 전에 백업을 만들고 별도 환경에서 한 번 복구한다.
- 복구 리허설에서 이전 공유 링크가 거부되고 팀별로 재발급한 새 링크만 동작하는지 확인한다.

파일럿에서는 기능 수보다 다음 신호를 우선 확인한다.

- 담당자가 없어 빠지는 책임을 더 일찍 발견하는가
- 반복 운영을 준비하는 시간이 줄어드는가
- 과거 결정의 이유를 다시 찾을 수 있는가
- 다음 담당자가 질문해야 하는 양과 시행착오가 줄어드는가

## 9. 초기 비목표

- 메신저나 화상 회의를 대체하는 자체 채팅
- 급여, 인사평가, 성적과 학사 행정 전체를 다루는 ERP
- 범용 문서 편집기나 파일 저장소 대체
- 복잡한 전자결재와 회계
- 모든 프로젝트 관리 기능을 한 번에 제공하는 것
- AI가 사람을 대신해 조직의 결정을 내리는 것

외부 문서, 캘린더와 메시징 연동은 핵심 흐름이 검증된 뒤 검토한다.

## 10. 미결정 사항

다음 항목은 이 기준선에서 확정하지 않는다.

- 조직 초대, 계정 비활성화·탈퇴와 단계 강화 신원 연결·병합
- 공유 워크스페이스 capability(권한 증표)를 대체할 팀·시즌·역할별 세부 권한과 감사 모델
- 파일럿 이후의 클라우드 공급자, 다중 호스트와 무중단 배포 방식
- 알림 채널과 WATCH 외 나머지 외부 서비스 연동
- 과금 방식
- 결정·인수인계 이외 도메인의 세부 상태 머신과 영구 삭제·보존 기간 정책

현재 백엔드는 명시한 `Account` 세션·ROUND·워크스페이스·WATCH 경로만 공개하고 그 밖의 요청을 거부한다. `Account` 세션, 워크스페이스 capability(권한 증표)와 WATCH Bearer는 서로 대체할 수 없는 별도 인증 경계다.
파일럿 공유 키는 최종 계정·권한 모델이 아니라 한정된 그룹에서 핵심 흐름을 검증하기 위한 임시 접근 방식이다.

## 결정 본문 형식

결정의 이유와 대안은 일반 텍스트 또는 Markdown으로 작성하고 저장 전에 미리 볼 수 있다. 기존 기록과 형식을 선택하지 않은 새 기록은 일반 텍스트로 유지한다. 형식을 바꿔도 원문은 보존한다. 제목·이름·책임은 일반 텍스트로 유지하며 Markdown의 원시 HTML, 이미지와 외부 임베드는 표시하지 않는다. 자격 증명이 없는 HTTP(S) 링크만 열 수 있고, 검색 화면은 서식 기호와 링크 주소를 제외한 표시 텍스트를 검색한다. 이전 시즌 기록과 인수인계 문서도 저장한 형식으로 표시한다.

## 역할 자료의 수동 확인

역할 자료 상세에서 사람이 확인한 최근 20건을 조회하고, 로그인 계정과 연결된 활성 구성원이 사용 가능·수정 필요와 500자 이내 메모를 남길 수 있다. 서버는 확인 당시 구성원 이름·자료 주소·자료 버전·시각을 보존한다. 자료를 수정하거나 보관·복원해 버전이 바뀌면 이전 확인으로 표시하며 새 확인이 필요하다. 종료 시즌·보관 자료에는 확인을 추가할 수 없다. WATCH 자동 점검 상태를 뜻하지 않으며 파일럿의 계정·구성원 연결은 공유 키 소유자가 직접 선택한다.

## 서비스 내 알림

오늘 화면의 내 알림함은 로그인 계정과 연결된 활성 구성원의 현재 역할을 기준으로 마감 임박·지연 업무와 수락 대기 인수인계를 표시한다. 기본 사전 알림은 24시간이며 계정별로 1~168시간과 세 가지 알림의 표시 여부를 저장한다. 설정은 모든 팀·기기에 적용하며 껐다 다시 켜도 기존 읽음 표시는 유지한다. 읽음은 계정별로 서버에 저장하며 마감 임박과 지연은 별도 알림이다. 마감 시각을 바꾸면 새 알림으로 보인다. 완료·회차 보관·인수인계 수락·취소·시즌 종료 뒤에는 해당 알림이 현재 목록에서 빠진다. 원본 회차·인수인계로 이동할 수 있고 열린 화면은 30초마다 갱신한다. 이메일·외부 메시지를 전송하거나 과거 알림 전체를 보관하는 기능은 포함하지 않는다.

‘내 알림’을 펼칠 때 조회를 시작하며, 접으면 자동 조회와 진행 중인 조회를 중단한다. ‘안 읽은 알림만’으로 목록을 좁힐 수 있고 읽음 처리한 항목은 해당 목록에서 빠진다. 필터를 해제하면 읽은 알림도 다시 표시한다. 필터 선택은 현재 화면에만 유지한다. 조회 권한이 없거나 로그인이 만료되면 자동 재시도·재조회를 멈추고 이전 목록과 안 읽은 개수를 감춘다. ‘다시 불러오기’로 재확인할 수 있다.

## 팀 초대와 권한 전환

[PRD-0009](../0009_team-account-access/spec.md)에 따라 팀별 계정 전환, 초대 생성·취소·수락, 권한 변경·회수와 최근 이력을 지원한다. 초대 목록은 유효·수락·취소·만료 상태를 구분하고 유효한 초대만 취소할 수 있다. 같은 탭에서 수락하지 않은 초대는 ‘내 팀’에서 다시 확인하거나 저장 정보만 지울 수 있다. 관리자만 구성원·시즌을 관리하고, 열람자는 일반 콘텐츠를 변경하지 못한다. 계정 팀의 인수인계 확인자는 로그인 계정과 연결된 구성원으로 제한한다. 운영자 복구 키로 첫 관리자 지정·관리자 복구를 지원하며 기존 팀을 자동 전환하지 않는다. 계정 권한 팀의 백업은 자동 복원 완료 전에 별도 권한·초대 검토가 필요하다.

### 계정의 참여 팀 탐색

로그인 사용자는 `/my-teams`에서 승인된 활성 구성원으로 참여한 계정 권한 팀을 조회하고 팀을 전환한다.
현재 권한·본인 구성원 이름·이동할 시즌을 표시하며 미종료 시즌을 우선한다. 상세 기준은 PRD-0009를 따른다.
공유 키 팀은 기존 공유 링크·기기별 최근 작업 공간으로 접근한다.

### 결정·자료의 수정 이력

- V36 적용 이후 결정·역할 자료의 수정·보관·복원은 원본 변경과 같은 트랜잭션에 변경 이력을 수정 없이 저장한다.
- 바뀐 항목만 변경 전후 값으로 남기고, 같은 값의 재저장은 이력을 만들지 않는다. 실패·롤백한 변경은 남기지 않는다.
- 로그인 계정의 식별자·당시 표시 이름·서버 시각을 저장한다. 비로그인 변경은 계정 식별자 없이 `공유 키 사용자`로 표시한다.
  결정의 작성자와 실제 변경자는 구분하며 기존 이름 선언을 로그인 신원으로 추정하지 않는다.
- 각 결정과 역할 자료의 `수정 이력`은 최근 50건을 최신순으로 보여 준다. 종료 시즌·보관 기록도 현재 읽기 권한으로 조회한다.
- 기존 수정 이력은 역산하지 않는다. 이력으로 원본을 자동 복원하는 기능은 제공하지 않는다.

### 자료 재확인 주기

자료 확인 기록에서 1~365일의 재확인 주기와 첫 확인일을 함께 지정하거나 해제한다. 기본값은 해제다.
설정은 로그인 계정과 연결된 활성 구성원 중 자료 수정 권한이 있는 사람이 변경한다. 종료 시즌·보관 자료에서는 변경하지 않는다.
다음 확인일 당일부터 기한이 된 것으로 표시한다. 날짜는 서버 `Clock`과 시즌 시간대를 기준으로 판단한다.
현재 자료를 `CONFIRMED`로 확인하면 확인 날짜에 간격을 더해 다음 확인일을 갱신한다. `NEEDS_UPDATE`는 기한을 유지한다.
확인 일정은 자료 내용의 버전과 분리한다. 일정만 바뀌어도 이전 내용 확인을 무효로 만들지 않으며,
일정 버전을 대조해 다른 사람의 변경이나 확인 후 갱신을 오래된 입력으로 덮어쓰지 않는다. 외부 알림은 발송하지 않는다.

## 여러 시즌의 기록 탐색

검색 화면에서 현재 시즌 또는 이 팀의 모든 시즌을 선택한다. 다른 시즌은 선택한 시점에 기존 권한과 팀·시즌·계정별 캐시로 조회한다. 결과에는 원본 시즌을 표시하고 역할 필터도 시즌별로 구분한다. 날짜 조건은 각 기록이 속한 시즌의 시간대를 적용한다. 시각 미상 기록은 기존 기간 검색 규칙을 따른다.

조회 중이거나 실패한 시즌은 안내하고, 실패 응답에 남은 캐시 기록은 결과에서 제외한다. 누락된 시즌을 다시 불러올 수 있다. 모든 시즌 검색 중에는 30초마다 다시 조회하며 접근 거부가 확인된 시즌은 주기·창 포커스·네트워크 복구에 따른 재조회를 멈춘다. 사용자가 ‘누락된 시즌 다시 불러오기’를 누르면 권한을 다시 확인한다. 현재 시즌의 원본 이동은 같은 화면에서 처리하고 다른 시즌의 활성 기록은 새 창에서 원본을 열어 검색 조건을 유지한다. 보관 기록은 검색 결과에서 내용을 확인한다.

## 계정 비활성화

내 계정 화면에서 기록 보존과 로그인 중지를 확인한 뒤 비활성화할 수 있다. 계정의 비활성 시각을 기록하고 모든 계정 세션을 만료한다. 자체 이메일 로그인과 기존 Google·Naver 신원의 재로그인, 비밀번호 재설정으로 계정을 다시 사용할 수 없으며 직접 재활성화하거나 로그인 정보를 삭제하는 탈퇴 기능은 제공하지 않는다.

계정 권한 팀에서 마지막 활성 관리자라면 다른 활성 관리자를 지정하기 전까지 요청 전체를 거부한다. 승인된 팀 권한을 회수하고 권한 이력에 계정 비활성화를 기록한다. 팀의 결정·자료·작성자·구성원 연결과 구성원 활동 상태는 보존한다. 공유 키 팀의 공유 접근 키는 별도 권한이므로 비활성화로 폐기하지 않는다.

새 구성원 연결·초대 수락·권한 부여와 외부 기능의 활성 계정 확인에서도 비활성 계정을 거부한다. 개인 CAL 구독은 같은 트랜잭션에서 해지를 예약하고 기존 재시도 처리로 외부 폐기를 완료한다. 이미 발급된 ROUND 참여권은 기존 만료 정책을 따르며 새 발급·갱신은 거부한다.

## 재확인할 자료 모아보기

오늘 화면은 시즌 시간대의 오늘 날짜까지 재확인 기한이 된 활성 자료를 기한·식별자 순으로 보여준다. 자료 이름·소속 역할·현재 활성 담당자와 확인 기한을 표시하며 담당자가 없거나 활동 종료 상태이면 지정이 필요하다고 안내한다. 목록에서 역할 상세로 이동해 실제 자료와 확인 기록을 확인한다. 사용 가능 확인·주기 변경·자료 보관 뒤 목록을 갱신하며 종료 시즌은 행동 목록을 표시하지 않는다.

## 대한민국 공휴일 조회

`Asia/Seoul` 시즌의 일정 화면에서 한국천문연구원 공휴일을 월별로 조회한다. 선택한 회차에 날짜가
있으면 그 달을 먼저 보여 주고 공휴일과 겹치는 모임일을 안내한다. 모임 날짜가 없으면 다음 자동
회차 예정일, 시즌 기간에 맞춘 오늘 날짜 순으로 사용한다. 다른 나라의 휴일로 해석하지 않는다.

공휴일 정보는 일정 확인용이며 자동 회차 생성·마감·완료 규칙을 바꾸지 않는다. 작년부터 내년까지
조회할 수 있고 정상 응답과 실패 응답은 연도별 1시간 캐시한다. 조회를 켜지 않은 환경, 공급자 오류·
연간 자료 미발표, 지원 연도 밖을 구분한다. 정상 조회한 달에만 공휴일이 없다고 안내한다.

## 작성 중 본문 초안

결정의 제목·이유·대안·본문 형식, 자료의 제목·주소·설명, 인수인계 항목의 본문을 현재 탭의 `sessionStorage`에 저장한다. 계정·팀·시즌·접근 키·기록 종류·기록 식별자의 SHA-256을 저장 키로 사용하며 원문 접근 키는 초안에 저장하지 않는다. 새 기록과 기존 기록의 초안을 구분한다. 다른 계정·시즌·접근 키로 열린 작성 창은 이전 초안을 불러오지 않는다.

같은 탭에서 24시간 이내의 유효한 초안만 복구하며 만료·손상 데이터는 작성 창을 열 때 제거한다. 복구는 사용자의 `초안 불러오기`로 본문에만 적용하며 작성자·소속 역할과 인수인계 분류는 현재 선택을 유지한다. 원본 본문이 바뀐 경우 최신 내용과 비교하도록 안내하며 자동 제출하지 않는다. 저장된 초안 삭제는 현재 입력을 지우지 않고, 이후 다시 편집하면 새 초안을 저장한다. 편집 중 본문을 작성 창을 처음 열었을 때의 내용으로 되돌리면 저장된 초안도 지워 지운 내용이 복구되지 않게 한다. 서버 저장 성공 시 해당 초안을 삭제한다. 삭제나 저장이 실패하면 화면에 알리고 서버에 저장된 기록의 성공을 취소하지 않는다. 초안은 서버 기록·멱등 요청 저널과 별개이며 다른 기기·브라우저와 동기화하지 않는다.
