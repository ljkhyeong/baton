# PRD-0001: BATON 제품 명세

- 상태: 초기 기준선
- 작성일: 2026-07-20
- 대상: 웹 서비스 MVP와 실제 그룹 스터디 파일럿

## 1. 제품 정의

BATON은 팀 업무와 인수인계를 관리하는 도구다. 담당자가 바뀌어도 업무·결정·자료 기록을 유지한다.

스터디, 동아리, 학생회, 학교 위원회, 회사의 프로젝트 팀과 TF처럼 여러 사람이 함께 일하는 조직을 대상으로 한다. 역할별 업무와 담당자, 반복 업무, 결정 이유와 인수인계 자료를 관리한다.

## 2. 해결하려는 문제

작은 조직은 별도의 운영 시스템 없이 메신저, 문서, 캘린더와 개인 기억에 의존하기 쉽다. 이때 다음 문제가 반복된다.

- 업무 방법이 기록되지 않아 담당자가 바뀌면 일이 누락된다.
- 반복 업무의 순서와 기준이 매번 다시 논의된다.
- 결정 결과만 남고 이유와 검토했던 대안은 사라진다.
- 인수인계가 임기나 프로젝트 종료 직전에 한꺼번에 이루어진다.
- 담당자 변경 전에 인수인계할 업무 방법과 접근 권한을 파악하기 어렵다.

BATON은 역할과 담당자, 반복 업무, 결정 기록, 인수인계를 함께 관리한다.

## 3. 제품 원칙

### 담당자가 바뀌어도 역할과 기록을 유지한다

책임은 사람에게 직접 고정하지 않고 역할에 둔다. 사람은 정해진 기간 동안 역할을 맡는다. 담당자가 바뀌어도 역할의 목적, 책임, 기록은 유지되어야 한다.

### 반복 업무를 회차별로 관리한다

한 번의 할 일뿐 아니라 모임 전·중·후, 매주, 매월처럼 되풀이되는 운영을 한눈에 확인할 수 있어야 한다.

### 결과와 함께 이유를 남긴다

결정에는 무엇을 정했는지뿐 아니라 이유, 검토한 대안, 영향을 받는 역할을 함께 남긴다.

### 인수인계는 마지막 날의 문서 작업이 아니다

역할을 수행하는 동안 책임, 반복 업무, 결정, 자료와 위험 신호가 계속 쌓이고, 필요할 때 인수인계 문서로 정리되어야 한다.

### 스터디에서 시작해 더 큰 조직으로 확장한다

첫 실제 사용처는 사용자가 참여하는 그룹 스터디다. 다만 제품 모델은 학교와 회사에도 적용할 수 있도록 조직 종류에 종속되지 않는 용어와 경계를 사용한다.

## 4. 핵심 개념

화면에서는 `반복 업무`, `인수인계`, `인수인계 문서`, `로그인 방법`을 공통 용어로 사용한다. API 필드명·열거형·기존 저장 데이터는 문구 변경과 관계없이 유지한다. 오늘 화면의 미완료 수는 선택한 회차의 미완료 업무 수이며, 인수인계 문서의 체크리스트 완료율은 보관하지 않은 항목 중 완료한 항목의 비율이다.

기록 검색의 상태는 `전체 기록`, `보관 안 함`, `보관됨`으로 표시한다. 인수인계의 `체크리스트 항목` 수는 보관한 항목을 제외하며, 전달 후에는 전달 당시 개수를 표시한다. 화면에서 로그인 세션 종료는 `로그아웃`으로 안내한다. 계정 비활성화는 로그인·팀 접근을 중지하는 기능이며 기록을 삭제하지 않는다는 점을 함께 설명한다.

역할 입력과 상세 화면, 인수인계 문서에서는 `역할 목적`, `담당 업무`, `주의사항`을 사용한다. 인수인계 항목의 상태는 `완료`와 `미완료`로 표시한다. `임시 기록 정리 재시도`는 브라우저에 남은 요청 정보를 정리하는 동작으로 안내하며, 서버의 업무 기록이나 작성 중인 본문 초안을 지우는 동작과 구분한다.

| 개념 | 의미 |
| --- | --- |
| 팀 | 지속적으로 운영 기록을 소유하는 기본 공간. 스터디, 동아리, 위원회, 회사 팀 등을 모두 포함한다. |
| 시즌 | 학기, 기수, 프로젝트처럼 시작과 종료가 있는 운영 기간이다. 조직의 달력 날짜와 모임·마감 시각을 해석할 IANA 시간대를 가진다. |
| 구성원 | 팀에 참여하는 사람이다. 역할과 동일하지 않다. |
| 역할 | 사람과 분리해 유지하는 목적과 책임의 묶음이다. |
| 역할 배정 | 구성원이 특정 기간 동안 역할을 맡는 관계다. |
| 반복 업무 | 특정 역할이 반복 수행할 일의 이름, 단계, 기한 문구, 선택적인 실제 마감 규칙과 실행 방법을 담은 정의다. |
| 운영 회차 | 시즌 안에서 사용자가 직접 만들거나 주간·격주 일정이 자동 생성하는 한 번의 운영 단위다. 수동·자동 회차는 이름·날짜를 정정할 수 있고, 모든 회차는 실행 기록을 지우지 않은 채 보관·복원할 수 있다. |
| 반복 업무 실행 | 회차를 만들 때 존재한 반복 업무 정의와 실제 마감을 복사한 회차별 실행 기록이다. 완료와 시간 상태는 다른 회차와 독립적이다. |
| 결정 기록 | 결정 내용, 이유, 검토한 대안, 작성자와 관련 역할을 담은 기록이다. |
| 자료 | 역할 수행과 인수인계에 필요한 문서나 외부 링크다. |
| 위험 신호 | 담당자 부재, 기록되지 않은 업무 방법, 반복 업무 지연처럼 확인이 필요한 문제다. |
| 인수인계 문서 | 역할의 목적·담당 업무·반복 업무·결정·자료·주의사항과 남은 일을 정리한 문서다. |
| 역할 인수인계 | 한 역할의 현재 담당자가 인수인계를 준비·전달·취소하고 다음 담당자가 수락하며 담당 기간을 전환하는 기록이다. |

이 표의 용어를 화면과 문서에서 사용한다. 데이터베이스 테이블, 상태 열거형, 세부 제약은 별도 명세를 따른다.

## 5. 핵심 사용자 경험

### 오늘

사용자는 현재 시즌의 시간대를 기준으로 지금 확인하거나 수행해야 할 예정·진행·지연·완료 반복 업무와 조직 연속성 위험을 본다. 각 위험은 현재 기록에서 판정한 이유와 바로 취할 다음 행동을 함께 보여 준다.

로그인 계정과 활동 중인 팀 구성원이 연결되어 있으면 `내 담당 업무`에서 현재 담당 역할의 미완료 반복 업무 실행과 자신에게 전달된 수락 대기 인수인계를 모아 본다. 보관된 회차와 완료 실행은 제외하고 회차 선택과 관계없이 현재 시즌 전체에서 찾으며, 마감순으로 정렬한다. 반복 업무는 해당 회차의 일정 화면으로, 인수인계는 해당 역할의 전달 내용으로 이동한다. 이동한 반복 업무 또는 인수인계 본문을 화면에 표시하고 키보드 초점도 함께 옮긴다. 미연결·로그인 필요·활동 종료·조회 실패를 구분하며, 개인화 표시는 공유 키 접근 권한이나 담당자 확인 계약을 바꾸지 않는다.

`주간 운영 요약`을 펼치면 로그인 계정과 활동 중인 팀 구성원 연결을 확인한 뒤 BRIEF의 최신
불변 요약을 조회한다. 사용자는 이번 주 요약 생성을 요청하고 생성 당시 주차·시각·신호 종류와
상태를 확인한다. 종료 시즌은 조회만 제공하며, 현재 운영 상태와 과거 요약을 구분한다.
서비스 연결·오류·재조회와 데이터 표시 범위는 [PRD-0008](../0008_brief-edition-query-and-generation/spec.md)이 소유한다.

### 역할

팀이 지속해서 필요로 하는 역할을 만들고 목적, 책임, 현재 담당 기간과 다음 담당자를 확인한다. 다음 시즌으로 이어 온 역할은 상세에서 `이전 시즌 기록 보기`를 펼쳐 당시 목적·책임·주의사항, 자료, 결정과 이유, 인수인계 항목을 조회한다. 현재 시즌은 그대로 유지하며 펼칠 때만 이전 시즌을 조회한다. 연결된 이전 시즌이나 역할이 없는 기존 이관 기록에서는 이 기능을 표시하지 않는다. 조회 실패 시 오류와 재시도를 제공하고 다른 역할의 자료로 대체하지 않는다. 필요한 자료만 골라 제목·링크·설명을 확인하면 현재 역할에 새 자료로 연결한다. 원본 기록은 유지하며, 종료 시즌과 전달 후 수락 대기 역할에서는 자료 추가를 막는다.

### 일정

모임 또는 업무의 전·중·후에 반복되는 반복 업무를 역할과 실제 마감에 연결하고 이번 회차의 진행 상황을 확인한다. 시즌의 주간·격주 일정을 켜 반복 회차를 자동으로 만들거나 필요할 때 수동 회차를 만든다. 더 이상 반복하지 않는 반복 업무 정의는 과거 회차의 실행 기록을 유지한 채 보관했다가 복원한다. 수동·자동 회차의 이름·날짜는 실행 기록을 유지한 채 정정한다. 자동 회차는 이번 회차만 건너뛰었다가 복원할 수 있으며 원래 발생일과 다음 반복 일정을 유지한다.

### 기록

중요한 결정을 이유와 대안까지 기록하고 관련 역할에서 다시 찾는다. 잘못 입력한 기록은 정정하고, 당장 사용하지 않는 기록은 삭제하지 않고 보관했다가 복원한다.

### 검색

현재 선택한 시즌의 결정, 인수인계 항목과 역할 자료를 하나의 시간 흐름에서 검색하고 기록 종류·관련 역할·활성/보관 상태·기간으로 좁힌다. 종료 시즌을 포함한 모든 시즌을 선택해 함께 탐색할 수 있다.

### 인수인계

역할별 인수인계 준비 상태를 확인하고 책임, 반복 업무, 결정, 자료, 조언과 남은 작업을 인수인계 문서로 정리한다. 인수인계 항목도 운영 중 정정하고 보관·복원할 수 있다. 현재 담당자는 다음 담당자와 새 담당 기간을 지정해 인수인계를 준비하고, 미완료 항목·자료 누락 경고를 확인한 뒤 전달한다. 다음 담당자가 수락하면 역할의 현재 담당자와 담당 기간이 함께 바뀌며, 수락 전에는 현재 담당자가 취소할 수 있다.

인수인계 문서 미리보기에는 역할의 목적·책임·주의사항과 활성 반복 업무·결정·자료, 보관하지 않은 모든 인수인계 항목을 담는다. 완료한 항목도 내용과 종류를 남기고 미완료 항목 수를 별도로 표시한다. 미리보기의 `인쇄 / PDF 저장` 버튼으로 인수인계 문서만 출력하거나 PDF로 저장할 수 있으며, 팀·시즌 이름과 자료 주소를 함께 출력한다. 이 버튼은 인쇄 호출 전에 주소의 접근 키를 제거하고 인쇄 종료·취소 뒤 복원해, 저장소가 막힌 환경에서도 다시 접속할 키를 잃지 않게 한다. 브라우저 메뉴·단축키 인쇄는 이 처리를 거치지 않으므로 키가 주소에 남아 있으면 반드시 미리보기 버튼을 사용하도록 안내한다. 출력물은 현재 조회한 기록의 사본이며 이후 변경을 자동 반영하지 않는다.

### 시즌

팀의 과거·현재 시즌을 전환해 조회하고, 운영 중인 시즌의 이름과 기간을 정정한다. 시즌을 명시적으로 종료하면 기록은 읽기 전용으로 보존한다. 다음 시즌을 시작할 때 이어 갈 역할과 활성 반복 업무 정의만 선택해 새 식별자로 복사하며 담당자·담당 기간과 실행 상태는 다시 정한다.

## 6. MVP 범위

- 팀과 기간이 있는 시즌을 만든다.
- 시즌의 이름·기간과 종료 상태를 관리하고 필요한 역할·반복 업무 정의를 다음 시즌으로 이어 간다.
- 구성원과 역할을 분리해 관리하고 역할 담당 기간을 기록한다.
- 역할의 목적, 책임과 반복 업무를 관리하고 사용하지 않는 반복 업무 정의를 실행 기록과 분리해 보관·복원한다.
- 시즌 시간대와 주간·격주 일정을 관리하고 반복 회차를 중복 없이 자동 생성한다.
- 반복 업무의 실제 마감과 이번 운영 회차의 예정·진행·지연·완료 여부를 확인한다.
- 결정 내용, 이유, 대안과 관련 역할을 기록한다.
- 결정의 결과·이유·대안, 인수인계 항목과 역할 자료를 역할과 시간 흐름으로 다시 찾는다.
- 역할에 자료와 위험 신호를 연결한다.
- 역할별 인수인계 문서를 준비하고 현재 담당자의 전달과 다음 담당자의 수락으로 역할 담당자·기간을 전환한다.
- 스터디를 모바일과 데스크톱 웹에서 실제 운영할 수 있다.

알림 시점, 권한 행렬과 보존 기간, 아직 구현하지 않은 영역의 세부 상태값은 실제 파일럿에서 필요한 흐름이 확인된 뒤 별도 결정한다.

### 첫 파일럿 구현 단위

첫 그룹 스터디 파일럿은 전체 MVP 중 다음 세로 흐름을 먼저 사용한다.

- 온보딩에서 한 팀, 한 시즌과 중복되지 않는 이름의 초기 구성원을 함께 만든다. 이름이 같은 사람은 구분 가능한 별칭을 사용한다. 빈 구성이 기본이며 `STUDY_V1`(스터디) 또는 `TEAM_V1`(팀 운영)을 고르면 역할 3개와 반복 업무 3개를 같은 트랜잭션으로 만든다. 담당자·담당 기간·실제 마감·반복 일정·운영 회차는 자동 지정하지 않는다. 생성 전 이름을 미리 보고 생성 후 내용을 수정할 수 있다. 템플릿의 담당자 공백도 기존 연속성 신호에 반영한다.
- 운영 중 기존 팀에 구성원을 추가한다. 구성원은 팀에 속하며 앞뒤 공백을 정리한 이름이 팀 안에서 정확히 중복되지 않게 하고, 응답이 유실되면 같은 요청으로 결과를 확인한다.
- 구성원의 현재 표시 이름을 정정하고 활동을 종료하거나 재개한다. 활동 종료 구성원도 기존 역할·결정 표시를 위해 조회하며, 새 역할 담당자와 결정 작성자 후보에서만 제외한다.
- 워크스페이스 공유 링크를 받은 구성원은 같은 서버 데이터를 읽고 쓴다. 열린 화면은 전경에서 10초마다 최신 워크스페이스를 확인하고, 창으로 돌아오거나 네트워크가 복구되면 즉시 다시 조회한다.
- 역할의 이름, 목적, 담당자, 담당 기간, 책임과 위험 신호를 만들고 운영 중 수정한다.
- 역할에 문서나 외부 자료 링크를 연결하고 제목, URL, 설명과 소유 역할을 운영 중 수정한다.
- 시즌의 반복 업무 정의와 모임 날짜 기준 실제 마감을 만들고 수정한다. 사용하지 않는 정의는 보관함으로 옮기며 이후 수동·자동 회차와 다음 시즌 선택에서 제외하고, 복원하면 다음 회차부터 다시 포함한다. 보관 이전 회차의 실행은 계속 확인하고 완료 처리할 수 있다. 시즌 IANA 시간대와 주간·격주 일정을 설정하면 `0..30`일 전에 회차를 중복 없이 자동 생성하며 일시 중지·재개할 수 있다. 활성 반복 업무가 모두 보관된 동안에는 예정 발생일의 커서만 전진시키고 빈 자동 회차를 만들지 않으며, 일정 화면은 활성 반복 업무를 기다리는 상태를 설명한다. 필요하면 이름과 시즌 안의 모임 날짜를 지정해 수동 회차도 만든다. 생성 시 활성 정의만 복사한 반복 업무 실행은 회차별로 완료 처리하고 시간 상태는 예정·진행·지연·완료로 구분한다. 수동·자동 회차의 이름·날짜를 정정하거나 어떤 회차든 보관·복원해도 실행 식별자, 스냅샷과 완료 상태는 유지한다.
- 결정 내용, 이유, 대안, 작성자와 관련 역할을 기록하고 운영 중 정정한다. 당장 사용하지 않는 결정은 보관함으로 옮겼다가 복원한다.
- 현재 시즌 또는 팀의 모든 시즌의 워크스페이스 프로젝션에서 결정·인수인계 항목·역할 자료를 통합 탐색한다. 기간은 시즌 시간대의 달력 날짜로 해석하며 자료 URL 문자열과 외부 문서 본문은 검색하지 않는다.
- 역할별 인수인계 항목을 만들고 내용·분류·소유 역할과 준비 여부를 갱신한다. 당장 사용하지 않는 항목은 보관함으로 옮겼다가 복원한다.
- 역할의 현재 담당자와 다음 담당자, 두 담당 기간을 고정해 역할 인수인계를 준비한다. 현재 담당자가 미완료 인수인계 항목과 빠진 자료 경고를 명시적으로 확인해 전달하고 다음 담당자가 수락하면 역할 담당자·기간을 한 번에 전환한다. 수락 전에는 현재 담당자가 인수인계를 취소할 수 있고, 완료·취소한 이력도 원본 시즌에 남긴다.
- 시즌 이름과 기간을 기존 회차·역할 담당 기간과 열린 역할 인수인계의 다음 담당 기간 경계 안에서 수정하고, 열린 인수인계가 없을 때 시즌을 명시적으로 종료하거나 후속 시즌이 없을 때 다시 연다.
- 다음 시즌 시작은 열린 역할 인수인계가 없을 때 현재 시즌을 종료하고 선택한 역할과 활성 반복 업무 정의만 새 UUID로 복사한다. 역할 담당자·담당 기간, 보관 반복 업무 정의, 회차·실행, 결정·인수인계 항목·역할 인수인계 이력·자료는 복사하지 않고 원본 시즌에 보존한다.
- 서버가 반환하는 팀 시즌 목록으로 과거 시즌을 전환해 조회한다. 종료 시즌에서는 일반 콘텐츠 변경을 막되 공유·접근 키 관리와 다음 시즌 시작은 유지한다.
- 운영자는 별도 복구 키로 종료 시즌의 이름만 정정할 수 있다. 종료 시각·기간·시간대·계보는 보존하며 일반 화면의 수정 권한은 넓히지 않는다.
- 서버 제품 데이터의 권위 있는 복제본은 MySQL을 단일 기준으로 사용하고 브라우저 `localStorage`와 이중 저장하지 않는다.
- 응답이 유실된 온보딩 재시도는 같은 워크스페이스로 복구되고 중복 팀을 만들지 않는다.
- 기존 팀 구성원·역할·반복 업무·회차·결정·인수인계 항목·역할 자료·역할 인수인계 준비 응답이 유실되어도 같은 요청을 재시도해 이미 생성된 항목을 되찾고 중복 기록을 만들지 않는다.
- 접근 키 회전·복구 응답이 유실되어도 같은 멱등 요청으로 이미 발급된 키를 회수한다. 더 최신 키 변경 뒤 과거 멱등 키를 재사용해 폐기된 링크를 되살릴 수는 없다.
- 백업을 복원하면 스냅샷 시점의 키 폐기 상태를 신뢰하지 않고 모든 팀의 기존 공유 키를 공개 전에 무효화한다. 운영자는 복구 대상 팀마다 새 멱등 키로 접근 키를 재발급하고 새 공유 링크를 다시 전달한다.
- 브라우저는 워크스페이스·콘텐츠 생성과 키 회전 멱등 정보를 요청 전에 내구 저장한다. Web Storage가 예외를 던지면 응답 유실을 안전하게 복구할 수 없으므로 요청을 시작하지 않는다.
- 검증된 워크스페이스는 이 브라우저의 최근 목록에서 다시 열 수 있고, 잘못된 공유 키가 기존 정상 키를 덮어쓰지 않는다.
- 접근 키를 저장하지 못한 작업 공간에서는 로그인을 새 탭으로 열고 원래 공유 링크가 있는 탭을 유지한다. 로그인 후 원래 탭으로 돌아오거나 새로고침하며, 접근 키를 로그인 복귀 쿼리에 넣지 않는다.
- 유출된 공유 키를 회전하고, 모든 구성원이 키를 잃으면 생성 권한과 분리된 파일럿 복구 키로 새 키를 복구한다.

공유 링크에는 워크스페이스 접근 키가 URL 프래그먼트로 포함된다. 서버는 원문 접근 키와 워크스페이스·콘텐츠 생성 및 키 변경 멱등 키를 저장하지 않고 SHA-256 기반 해시만 저장한다. 접근 키 원문은 최초 성공 응답과 동일 멱등 요청의 응답 유실 복구 때만 반환된다. 공급자 중립 `Account`와 동일 출처 세션을 도입한 뒤에도 이 키는 기존 워크스페이스 전체를 읽고 쓰는 파일럿 capability(권한 증표)로 남으며 `Account` 세션이 암묵적으로 대체하지 않는다. 공유 키 방식을 유지하는 팀은 링크를 아는 사람이 읽고 쓸 수 있다. PRD-0009에 따라 운영자가 계정 권한으로 전환한 팀에서는 기존 공유 키를 거부하고 관리자·구성원·열람자 권한을 적용한다. 공유 키 팀에서 역할 인수인계의 `confirmedByMemberId`는 이전·다음 담당자 명의의 확인 선언일 뿐 실제 로그인 사용자의 신원을 인증한 감사 증거가 아니다.

다음 항목은 첫 파일럿 구현 단위에 포함하지 않는다.

- 모든 제품 기록의 영구 삭제
- 여러 팀을 한 계정에서 선택하는 화면
- 조직 초대, 역할별 세부 권한과 사용자별 감사 이력
- 계정 비활성화·탈퇴와 단계 강화 신원 연결·병합
- 마감·지연을 외부 메시징·메일·캘린더 채널로 보내는 알림

## 7. 현재 구현 상태

현재 프런트엔드는 실제 파일럿 온보딩과 서버 저장 워크스페이스를 제공한다.

`내 팀`의 `모든 팀의 내 할 일`은 승인된 계정 권한 팀의 종료하지 않은 모든 시즌에서 현재 담당 역할의 미완료 반복 업무와 수락 대기 인수인계를 모은다. 전체·기한 지난 반복 업무·수락 대기 인수인계로 좁히고 원본 회차나 인수인계 화면으로 이동한다. 공유 키 팀과 종료 시즌은 포함하지 않는다. 업무는 기존 워크스페이스 API로 조회하고 전경에서 30초마다 갱신한다. 일부 조회가 실패하면 누락 안내를 표시하며, 팀 권한 거부가 확인된 팀의 캐시 데이터는 업무 목록에서 제외한다. 마감은 해당 시즌 시간대로 표시한다.

- Google·Naver·자체 이메일 계정의 로그인, 자체 이메일 등록·검증과 로그아웃 화면을 제공한다. 인증 정보는 브라우저 저장소의 토큰이 아니라 동일 출처 서버 세션 쿠키로 유지한다.
- 인증된 자체 이메일 계정은 30분짜리 일회용 메일 링크로 비밀번호를 재설정할 수 있다. 완료 후 기존 계정 세션은 모두 다음 요청에서 거부하고 새 비밀번호로 다시 로그인한다. 계정 존재 여부를 접수 응답에 노출하지 않으며 공유 접근 키·발급된 ROUND 참여권은 유지한다. 메일 요청 기능은 기본 비활성화하고 실제 SMTP 검증 후 가입과 독립적으로 켠다.
- 로그인한 사용자는 `/account`에서 계정 표시 이름과 연결된 로그인 방법을 확인한다. 자체 이메일 계정은 현재 비밀번호를 확인해 새 비밀번호로 바꿀 수 있고, 모든 계정은 현재 브라우저를 포함한 모든 기기의 기존 세션을 종료할 수 있다. 두 작업은 새 로그인을 요구하지만 팀 공유 접근 키와 이미 발급된 ROUND 참여권은 유지한다.
- `/account`의 **내 캘린더 구독**에서 팀·시즌별 본인 구독을 모아 보고 상태를 확인하거나 해제한다. 팀 권한을 잃은 구독도 관리하며 주소는 다시 노출하지 않는다. 발급 조건과 CAL 연동 범위는 [PRD-0006](../0006_calendar-integration-contract/spec.md)을 따른다.
- 구성원 관리에서 로그인 계정을 기존 활동 중 구성원 한 명과 명시적으로 연결하고, 새로고침 뒤 서버에서 팀별 연결 상태를 다시 확인한다. 연결 사실은 구성원 활동 종료 뒤에도 보존하며, 로그인 복귀 경로에는 워크스페이스 접근 키를 복제하지 않는다.
- 팀, 시즌 기간과 초기 구성원을 등록하고 공유 링크를 만든다.
- 역할 화면에서 현재 팀의 구성원을 추가하고 표시 이름과 활동 상태를 관리한다. 활동 종료 구성원은 기존 역할·결정 기록에 남지만 새 담당자와 작성자 선택에서는 제외하며 활동을 재개할 수 있다. 같은 팀의 중복 이름은 활동 상태와 관계없이 구분 가능한 별칭을 안내하고, 추가 응답 유실 시 같은 멱등 요청으로 생성 결과를 복구한다.
- 오늘, 역할, 일정, 기록, 인수인계, 검색 화면을 서버 프로젝션으로 표시한다.
- 파일럿의 오늘 날짜, 시즌 진행률과 종료까지 남은 날짜는 브라우저 위치와 관계없이 시즌의 IANA 시간대에 해당하는 달력 날짜를 기준으로 계산한다. 기존·최초 시즌의 기본값은 `Asia/Seoul`이고 다음 시즌은 원본 시간대를 이어 받는다. 일반 시즌은 시작일에 0%, 종료일에 100%로 표시하며 종료일 다음 날부터 지난 시즌 안내를 보여 준다. 시작일과 종료일이 같은 시즌은 해당 날짜에 `1 / 1주`, 100%로 표시한다.

- 공용 대화상자와 작은 화면의 역할 상세 서랍형 패널은 처음 열릴 때 초점을 내부로 옮겨 순환시키고, `Escape`로 닫은 뒤 진입한 컨트롤로 돌려보낸다. 닫힌 서랍형 패널은 키보드와 화면 읽기 도구의 접근을 막으며, 인수인계의 역할 탭은 좌우 방향키와 `Home`·`End`로 이동하고 선택한 탭 패널과 연결된다.

- 온보딩은 완료 여부를 확인하지 못한 워크스페이스 생성 요청의 팀·시즌·기간·구성원 수·선택한 템플릿과 기록 시각을 복구 목록으로 보여 준다. 템플릿도 같은 요청을 식별하는 입력에 포함한다. 사용자는 저장된 입력을 불러와 같은 멱등 키로 생성 결과를 확인하며, 기존 공유 링크 등으로 결과를 별도로 확인한 요청만 경고를 거쳐 개별적으로 폐기할 수 있다. 자동 만료와 일괄 폐기는 제공하지 않고, 다른 탭에서 생성 결과를 확인 중인 복구 기록의 폐기는 막는다. 선택한 복구 기록이 다른 탭에서 사라지거나 페이로드·기록 시각이 바뀌거나 신규 생성 초안이 다른 탭의 요청과 경합해 전송되지 않아도 같은 입력을 새 요청으로 자동 전환하지 않으며, 동일한 전체 스냅샷이 확인되면 그 멱등 키에 결속한다. 그 밖에는 사용자가 기존 결과를 확인한 뒤 명시적으로 전환해야 새 멱등 키를 발급한다. 탭 사이의 생성 요청을 안전하게 직렬화할 수 없는 브라우저에서는 신규 생성·결과 확인·복구 목록에서 삭제를 차단한다.
- 접근 키 변경은 같은 팀의 다른 탭과 멱등 저널 조회·생성부터 서버 결과 분류와 검증 정리까지 하나의 Web Lock 임계 구역에서 처리한다. 경쟁한 탭은 새 멱등 저널이나 POST 요청을 만들지 않고 먼저 시작한 탭의 완료를 안내하며, 이 직렬화를 지원하지 않는 브라우저에서는 회전을 시작하지 않는다.
- 접근 키 변경이나 결과 복구를 요청한 뒤 작업 공간을 떠나면 늦은 응답으로 저장 키와 현재 주소를 바꾸지 않는다. 미완료 멱등 기록은 유지하며, 작업 공간을 다시 열어 같은 요청으로 결과를 확인한다. 로그아웃이나 이 기기 권한 제거로 지운 접근 키도 늦은 응답이 다시 저장하지 않는다.
- 워크스페이스·다음 시즌 생성이나 자체 이메일 로그인 요청 뒤 해당 화면을 떠나면 늦은 성공 응답이 현재 경로를 덮어쓰지 않는다. 접근 키 저장·멱등 저널 정리와 새 로그인 세션 조회처럼 완료돼야 하는 백그라운드 처리는 유지하고, 다시 진입하면 저장된 권한·서버 상태·세션 캐시에서 결과를 확인한다.
- 콘텐츠 생성과 키 관리 화면의 접근 키 회전은 완료 전 멱등 정보를 내구 저장할 수 없으면 요청을 차단한다. 콘텐츠 생성은 같은 브라우저의 탭 사이에서 요청 결과가 확정될 때까지 한 번에 하나씩 처리하고, 다른 탭의 생성이 진행 중이면 새 요청을 전송하지 않는다. 이 직렬화를 지원하지 않는 브라우저에서도 콘텐츠 생성을 시작하지 않는다. 콘텐츠 생성이나 접근 키 회전 요청이 진행되는 동안에는 해당 대화상자의 다른 동작과 닫기·`Escape`·배경 닫기를 막아 같은 의도를 별도 UI 세션에서 중복 제출하지 않게 한다. 서버 반영 뒤 응답만 유실되면 저장한 동일 멱등 요청으로 생성된 리소스나 새 키를 회수한다. 워크스페이스·콘텐츠 생성과 키 회전 멱등 저널은 오류를 같은 요청 재확인, 새 요청 가능, 기존 결과 확인 후 새 요청 가능으로 구분하고, 결정적 종료나 성공 뒤에는 대상 스냅샷 삭제를 시도한다. Web Storage의 `setItem`과 `removeItem`이 예외 없이 끝나면 표준 API 계약에 따라 성공으로 간주하며 쓰기 후 읽기 검증이나 `null` 삭제 표식을 별도로 만들지 않는다. 저장소가 예외를 던져 완료 기록 정리가 필요하면 새로고침이나 작업 종류 전환 뒤에도 그 상태를 유지하고, 입력 양식 검증과 독립된 명시적 정리 동작을 제공하며, 정리가 성공하기 전에는 모든 콘텐츠 생성의 새 멱등 키 발급과 전송을 차단한다. 복구 결과가 만료되어 기존 리소스가 이미 생겼을 수 있는 경우에는 기록 정리 뒤에도 사용자가 기존 결과를 확인하고 명시적으로 재시도해야 새 멱등 키를 발급한다.
- 콘텐츠 생성 대기 기록은 POST 전에 `requestGuard`를 Web Lock 임계 구역에서 내구 저장한다. 결과 미확정 보호 기록이 하나라도 남으면 전역에서 가장 오래된 보호 기록의 같은 팀·시즌·작업 종류·정규화한 페이로드만 동일 멱등 키로 재확인하고, 그 밖의 모든 콘텐츠 새 멱등 키 발급과 전송은 차단한다. `cleanupRequired`가 남은 요청은 보호 기록 재확인보다 완료 기록 정리를 우선하며, 결과 미확정 보호 기록만 있는 항목은 자동으로 삭제하지 않는다.

백엔드는 팀·시즌·구성원·역할·역할 자료·반복 업무 정의·운영 회차·반복 업무 실행·결정·인수인계 항목·역할 인수인계의 MySQL 영속 모델, Flyway 마이그레이션과 `/api/v1` 파일럿 계약을 제공한다. 애플리케이션 경계에서 공유 키, 워크스페이스·구성원을 포함한 콘텐츠 생성과 키 변경의 멱등성, 역할·자료·반복 업무·회차·실행·결정·인수인계의 소속과 불변식, 분리된 생성 게이트와 운영자 복구 권한을 검증한다. 역할 인수인계는 역할과 분리한 이력 애그리거트로 `PREPARING → TRANSFERRED → ACCEPTED` 또는 `CANCELLED` 상태를 보존한다. 준비 시 두 담당자와 다음 담당 기간을 고정하고, 전달 시 활성·미완료 인수인계 항목 수와 자료 수를 스냅샷하며 누락 위험을 명시적으로 확인하게 한다. 수락은 역할의 현재·다음 담당자와 담당 기간을 원자적으로 전환하고, 역할마다 열린 인수인계는 하나만 허용한다. 전달 뒤에는 역할·인수인계 항목·자료 변경을 수락 또는 취소 전까지 막고, 열린 인수인계는 시즌 종료와 다음 시즌 시작도 막는다. 구성원은 팀에 속하지만 추가 요청의 시즌 경로는 접근 검증과 멱등 범위를 정하는 문맥으로 사용하며, 활동 상태와 관계없이 이름을 팀 안에서 유일하게 유지한다. 역할은 시즌별 스냅샷이고 같은 이름도 다른 시즌에는 사용할 수 있다. 다음 시즌 전환은 선택한 역할과 활성 반복 업무 정의만 새 UUID로 복사하고 계보와 시즌 시간대를 이어 받으며 담당자·기간을 초기화한다. 회차 일정, 회차·실행, 보관 반복 업무 정의, 결정·인수인계 항목·역할 인수인계 이력·자료는 복사하지 않아 원본 시즌의 기록으로 남는다. 활동 종료는 기존 역할·결정과 역할 인수인계 참여자 참조를 보존하는 가역 상태 변경이고, 새 역할 담당자·결정 작성자·역할 인수인계 참여자에는 활동 중 구성원만 배정한다. 자료 URL은 사용자 정보가 없는 `http` 또는 `https` 전체 주소만 허용하고 서버가 링크 대상을 조회하거나 신뢰성을 판정하지 않는다. 회차 생성은 현재 활성 반복 업무 정의와 실제 마감 규칙 전체를 실행 기록과 UTC `deadlineAt`으로 한 번만 복사한다. 정의를 추가·수정·보관·복원해도 이미 만든 회차의 실행은 바뀌지 않고 다음 회차부터 반영된다. 수동·자동 회차 이름·날짜 수정과 보관·복원은 기존 실행 식별자·스냅샷·상태를 바꾸지 않으며, 날짜 정정 때 복사된 규칙으로 실제 마감을 다시 계산한다. 자동 회차는 원래 발생일을 보존하고 시즌 시간대의 기존 모임 시각을 새 날짜에 적용한다. 보관된 회차 이름과 자동 회차의 원래 발생일은 계속 예약된다. 자동 생성기는 기본 1분 간격으로 데이터베이스 상태를 확인하고 한 실행 주기에서 모든 활성 시즌 후보와 시즌별 최대 8개 발생을 `Team` 공유 잠금 뒤 `Season` 배타 잠금으로 처리한다. 발생일 유일 제약과 전진 커서로 재실행에도 같은 자동 회차를 중복 생성하지 않는다. 처리 시점에 활성 반복 업무가 없으면 해당 발생일의 커서만 전진시키고 실행이 없는 자동 회차는 저장하지 않는다. 콘텐츠 생성은 멱등 예약과 리소스 저장을 한 트랜잭션으로 처리하고, 접근 키 변경과 구성원·시즌·역할·역할 자료·반복 업무 정의·시즌 회차·회차 실행·결정·인수인계 항목·역할 인수인계의 겹친 수정은 낙관적 잠금으로 조용한 덮어쓰기를 막는다. 일반 변경은 `Team → Season` 공유 잠금 아래 종료 여부를 확인하고 시즌 종료·전환은 같은 순서의 배타 잠금으로 직렬화한다. 구성원 활동 종료와 새 역할·결정·역할 인수인계 참여자 배정, 회차 보관과 실행 완료, 역할 인수인계 상태와 자식 인수인계 항목·자료 변경은 각 부모 행의 잠금을 공유해 검증 뒤 상태 변경이 끼어들지 않게 한다. 반복 업무 정의 보관·복원은 `Season` 배타 잠금으로 수동·자동 회차 생성 및 일반 반복 업무 변경과 직렬화한다. 실제 행 잠금 대기가 제한을 넘으면 접근 키 또는 콘텐츠 충돌로 끝내고, 일반 쿼리·트랜잭션·커넥션 시간 초과는 도메인 충돌로 오분류하지 않는다. 구성원 활동 종료와 시즌 종료는 각각 UTC `deactivatedAt`, `endedAt`을 기록하고 반복 업무 정의·회차·결정·인수인계 항목의 보관은 UTC `archivedAt`을 기록하는 가역 상태 변경이며 영구 삭제가 아니다. 기존 `routines.status`는 `회차 도입 이전 기록` 회차의 실행 상태로 이관하며 실제 과거 날짜를 알 수 없어 해당 회차의 날짜는 운영자가 실제 날짜로 정정할 때까지 비어 있다. 기존 기한 문구에서는 실제 마감을 복원할 수 없어 구조화된 마감은 비어 있으며 해당 실행은 `UNSCHEDULED`로 표시한다. 프로덕션 파일럿은 동일 출처 HTTPS와 내부 전용 MySQL, 모든 기존 공유 키를 강제 폐기하고 팀별 최신 대표 시즌 재발급 대상을 남기는 백업·복구 스크립트를 제공한다. 공급자 중립 `Account`·신원, 이메일 검증 아웃박스, 동일 출처 세션, 워크스페이스 구성원 관리의 기존 구성원 멤버십 연결·현재 상태 조회와 ROUND 참여권 발급 기반도 제공한다. 역할 자료 화면에서는 서버가 관리하는 ROUND 방 매핑을 생성하고 입장하거나 종료할 수 있다. 승인된 계정 권한 팀의 내 팀 목록과 팀 전환, 초대·세부 권한을 제공한다. 외부 알림 채널은 아직 구현하지 않았다.

BATON 본체가 링크 대상을 조회하지 않는다는 원칙은 계속 유지한다. 채택된 WATCH 연동을 켠 환경에서는 BATON이 감시 적격 역할 자료의 목표 스냅샷을 같은 MySQL 트랜잭션의 아웃박스에 기록하고, 별도 서비스인 WATCH가 커밋 이후 공개 URL의 제한된 도달 가능성만 비동기로 점검한다. WATCH는 상태 변경 이벤트를 최소 한 번 전달 방식으로 직접 HTTPS 전달하고 BATON은 별도 Bearer로 보호한 `/api/v1/internal/resource-health-events`에서 이벤트 ID별 불변 인박스에 원자적으로 저장한다. 동일 재전송은 최초 접수증을 반환하고 같은 이벤트 ID의 다른 이벤트 전체 내용은 거부하며, 서로 다른 이벤트는 소스 리비전과 도착 순서에 관계없이 모두 보존한다. 인박스는 `RoleResource` 존재 조회나 FK에 의존하지 않는다. WATCH 결과는 자료의 존재·권한·신뢰성을 바꾸지 않는 비권위 상태이며 상태 프로젝션·UI와 인박스 보존 정책은 아직 구현하지 않았다. 저장소 구현만으로 실제 공개 WATCH→BATON 전달과 운영 활성화를 완료했다고 보지 않는다.

## 8. 첫 파일럿

사용자가 참여하는 그룹 스터디를 첫 운영 현장으로 삼는다.

- 실제 스터디의 시즌과 역할을 등록한다.
- 공유 링크를 파일럿 구성원에게 전달하고 같은 기록이 각 브라우저에서 보이는지 확인한다.
- 실제 HTTPS 주소를 서로 다른 두 기기에서 열어 공유 링크와 변경 동기화를 확인한다.
- 매 회차 전·중·후 반복 업무를 BATON에서 확인한다.
- 실제 운영에서 중단한 반복 업무 정의를 보관해 과거 회차 실행과 완료 상태가 남는지 확인하고, 복원한 정의가 새 회차부터 다시 포함되는지 확인한다. 모든 정의를 보관한 동안에는 빈 자동 회차가 생기지 않고 일정 화면이 활성 반복 업무 대기 상태를 설명하는지도 확인한다.
- 운영 방식이 바뀔 때 이유와 대안을 남긴다.
- 과거 결정 한 건의 결과·이유·관련 역할을 별도 설명 없이 검색 화면에서 다시 찾는다.
- 역할 교대 전에 현재 담당자가 인수인계를 전달하고 실제 다음 담당자가 내용을 확인해 수락한다.
- 별도 설명 없이도 다음 행동을 찾을 수 있는지 관찰한다.
- 실제 기록을 넣기 전에 백업을 만들고 별도 환경에서 한 번 복구한다.
- 복구 리허설에서 이전 공유 링크가 거부되고 팀별로 재발급한 새 링크만 동작하는지 확인한다.

파일럿에서는 기능 수보다 다음 신호를 우선 확인한다.

- 담당자가 없어 빠지는 책임을 더 일찍 발견하는가
- 반복 운영을 준비하는 시간이 줄어드는가
- 과거 결정의 이유를 다시 찾을 수 있는가
- 다음 담당자가 질문해야 하는 양과 시행착오가 줄어드는가

## 9. 초기 비목표

- 메신저나 화상 회의를 대체하는 자체 채팅
- 급여, 인사평가, 성적과 학사 행정 전체를 다루는 ERP
- 범용 문서 편집기나 파일 저장소 대체
- 복잡한 전자결재와 회계
- 모든 프로젝트 관리 기능을 한 번에 제공하는 것
- AI가 사람을 대신해 조직의 결정을 내리는 것

외부 문서, 캘린더와 메시징 연동은 핵심 흐름이 검증된 뒤 검토한다.

## 10. 미결정 사항

다음 항목은 이 기준선에서 확정하지 않는다.

- 조직 초대, 계정 비활성화·탈퇴와 단계 강화 신원 연결·병합
- 공유 워크스페이스 capability(권한 증표)를 대체할 팀·시즌·역할별 세부 권한과 감사 모델
- 파일럿 이후의 클라우드 공급자, 다중 호스트와 무중단 배포 방식
- 알림 채널과 WATCH 외 나머지 외부 서비스 연동
- 과금 방식
- 결정·인수인계 이외 도메인의 세부 상태 머신과 영구 삭제·보존 기간 정책

현재 백엔드는 명시한 `Account` 세션·ROUND·워크스페이스·WATCH 경로만 공개하고 그 밖의 요청을 거부한다. `Account` 세션, 워크스페이스 capability(권한 증표)와 WATCH Bearer는 서로 대체할 수 없는 별도 인증 경계다.
파일럿 공유 키는 최종 계정·권한 모델이 아니라 한정된 그룹에서 핵심 흐름을 검증하기 위한 임시 접근 방식이다.

## 결정 본문 형식

결정의 이유와 대안은 일반 텍스트 또는 Markdown으로 작성하고 저장 전에 미리 볼 수 있다. 기존 기록과 형식을 선택하지 않은 새 기록은 일반 텍스트로 유지한다. 형식을 바꿔도 원문은 보존한다. 제목·이름·책임은 일반 텍스트로 유지하며 Markdown의 원시 HTML, 이미지와 외부 임베드는 표시하지 않는다. 자격 증명이 없는 HTTP(S) 링크만 열 수 있고, 검색 화면은 서식 기호와 링크 주소를 제외한 표시 텍스트를 검색한다. 이전 시즌 기록과 인수인계 문서도 저장한 형식으로 표시한다.

## 역할 자료의 수동 확인

역할 자료 상세에서 사람이 확인한 최근 20건을 조회하고, 로그인 계정과 연결된 활성 구성원이 사용 가능·수정 필요와 500자 이내 메모를 남길 수 있다. 서버는 확인 당시 구성원 이름·자료 주소·자료 버전·시각을 보존한다. 자료를 수정하거나 보관·복원해 버전이 바뀌면 이전 확인으로 표시하며 새 확인이 필요하다. 종료 시즌·보관 자료에는 확인을 추가할 수 없다. WATCH 자동 점검 상태를 뜻하지 않으며 파일럿의 계정·구성원 연결은 공유 키 소유자가 직접 선택한다.

## 서비스 내 알림

오늘 화면의 내 알림함은 로그인 계정과 연결된 활성 구성원의 현재 역할을 기준으로 마감 임박·지연 업무와 수락 대기 인수인계를 표시한다. 기본 사전 알림은 24시간이며 계정별로 1~168시간과 세 가지 알림의 표시 여부를 저장한다. 설정은 모든 팀·기기에 적용하며 껐다 다시 켜도 기존 읽음 표시는 유지한다. 읽음은 계정별로 서버에 저장하며 마감 임박과 지연은 별도 알림이다. 마감 시각을 바꾸면 새 알림으로 보인다. 완료·회차 보관·인수인계 수락·취소·시즌 종료 뒤에는 해당 알림이 현재 목록에서 빠진다. 원본 회차·인수인계로 이동할 수 있고 열린 화면은 30초마다 갱신한다. 이메일·외부 메시지를 전송하거나 과거 알림 전체를 보관하는 기능은 포함하지 않는다.

## 팀 초대와 권한 전환

[PRD-0009](../0009_team-account-access/spec.md)에 따라 팀별 계정 전환, 초대 생성·취소·수락, 권한 변경·회수와 최근 이력을 지원한다. 관리자만 구성원·시즌을 관리하고, 열람자는 일반 콘텐츠를 변경하지 못한다. 계정 팀의 인수인계 확인자는 로그인 계정과 연결된 구성원으로 제한한다. 운영자 복구 키로 첫 관리자 지정·관리자 복구를 지원하며 기존 팀을 자동 전환하지 않는다. 계정 권한 팀의 백업은 자동 복원 완료 전에 별도 권한·초대 검토가 필요하다.

### 계정의 참여 팀 탐색

로그인 사용자는 `/my-teams`에서 승인된 활성 구성원으로 참여한 계정 권한 팀을 조회하고 팀을 전환한다.
현재 권한·본인 구성원 이름·이동할 시즌을 표시하며 미종료 시즌을 우선한다. 상세 기준은 PRD-0009를 따른다.
공유 키 팀은 기존 공유 링크·기기별 최근 작업 공간으로 접근한다.

### 결정·자료의 수정 이력

- V36 적용 이후 결정·역할 자료의 수정·보관·복원은 원본 변경과 같은 트랜잭션에 불변 이력을 저장한다.
- 바뀐 항목만 변경 전후 값으로 남기고, 같은 값의 재저장은 이력을 만들지 않는다. 실패·롤백한 변경은 남기지 않는다.
- 로그인 계정의 식별자·당시 표시 이름·서버 시각을 저장한다. 비로그인 변경은 계정 식별자 없이 `공유 키 사용자`로 표시한다.
  결정의 작성자와 실제 변경자는 구분하며 기존 이름 선언을 로그인 신원으로 추정하지 않는다.
- 각 결정과 역할 자료의 `수정 이력`은 최근 50건을 최신순으로 보여 준다. 종료 시즌·보관 기록도 현재 읽기 권한으로 조회한다.
- 기존 수정 이력은 역산하지 않는다. 이력으로 원본을 자동 복원하는 기능은 제공하지 않는다.

### 자료 재확인 주기

자료 확인 기록에서 1~365일의 재확인 주기와 첫 확인일을 함께 지정하거나 해제한다. 기본값은 해제다.
설정은 로그인 계정과 연결된 활성 구성원 중 자료 수정 권한이 있는 사람이 변경한다. 종료 시즌·보관 자료에서는 변경하지 않는다.
다음 확인일 당일부터 기한이 된 것으로 표시한다. 날짜는 서버 `Clock`과 시즌 시간대를 기준으로 판단한다.
현재 자료를 `CONFIRMED`로 확인하면 확인 날짜에 간격을 더해 다음 확인일을 갱신한다. `NEEDS_UPDATE`는 기한을 유지한다.
확인 일정은 자료 내용의 버전과 분리한다. 일정만 바뀌어도 이전 내용 확인을 무효로 만들지 않으며,
일정 버전을 대조해 다른 사람의 변경이나 확인 후 갱신을 오래된 입력으로 덮어쓰지 않는다. 외부 알림은 발송하지 않는다.

## 여러 시즌의 기록 탐색

검색 화면에서 현재 시즌 또는 이 팀의 모든 시즌을 선택한다. 다른 시즌은 선택한 시점에 기존 권한과 팀·시즌·계정별 캐시로 조회한다. 결과에는 원본 시즌을 표시하고 역할 필터도 시즌별로 구분한다. 날짜 조건은 각 기록이 속한 시즌의 시간대를 적용한다. 시각 미상 기록은 기존 기간 검색 규칙을 따른다.

조회 중이거나 실패한 시즌은 안내하고, 실패 응답에 남은 캐시 기록은 결과에서 제외한다. 누락된 시즌을 다시 불러올 수 있다. 모든 시즌 검색 중에는 30초마다 다시 조회하며 접근 거부가 확인된 시즌의 자동 재조회는 멈춘다. 현재 시즌의 원본 이동은 같은 화면에서 처리하고 다른 시즌의 활성 기록은 새 창에서 원본을 열어 검색 조건을 유지한다. 보관 기록은 검색 결과에서 내용을 확인한다.

## 계정 비활성화

내 계정 화면에서 기록 보존과 로그인 중지를 확인한 뒤 비활성화할 수 있다. 계정의 비활성 시각을 기록하고 모든 계정 세션을 만료한다. 자체 이메일 로그인과 기존 Google·Naver 신원의 재로그인, 비밀번호 재설정으로 계정을 다시 사용할 수 없으며 직접 재활성화하거나 로그인 정보를 삭제하는 탈퇴 기능은 제공하지 않는다.

계정 권한 팀에서 마지막 활성 관리자라면 다른 활성 관리자를 지정하기 전까지 요청 전체를 거부한다. 승인된 팀 권한을 회수하고 권한 이력에 계정 비활성화를 기록한다. 팀의 결정·자료·작성자·구성원 연결과 구성원 활동 상태는 보존한다. 공유 키 팀의 공유 접근 키는 별도 권한이므로 비활성화로 폐기하지 않는다.

새 구성원 연결·초대 수락·권한 부여와 외부 기능의 활성 계정 확인에서도 비활성 계정을 거부한다. 개인 CAL 구독은 같은 트랜잭션에서 해지를 예약하고 기존 재시도 처리로 외부 폐기를 완료한다. 이미 발급된 ROUND 참여권은 기존 만료 정책을 따르며 새 발급·갱신은 거부한다.

## 재확인할 자료 모아보기

오늘 화면은 시즌 시간대의 오늘 날짜까지 재확인 기한이 된 활성 자료를 기한·식별자 순으로 보여준다. 자료 이름·소속 역할·현재 활성 담당자와 확인 기한을 표시하며 담당자가 없거나 활동 종료 상태이면 지정이 필요하다고 안내한다. 목록에서 역할 상세로 이동해 실제 자료와 확인 기록을 확인한다. 사용 가능 확인·주기 변경·자료 보관 뒤 목록을 갱신하며 종료 시즌은 행동 목록을 표시하지 않는다.

## 작성 중 본문 초안

결정의 제목·이유·대안·본문 형식, 자료의 제목·주소·설명, 인수인계 항목의 본문을 현재 탭의 `sessionStorage`에 저장한다. 계정·팀·시즌·접근 키·기록 종류·기록 식별자의 SHA-256을 저장 키로 사용하며 원문 접근 키는 초안에 저장하지 않는다. 새 기록과 기존 기록의 초안을 구분한다. 다른 계정·시즌·접근 키로 열린 작성 창은 이전 초안을 불러오지 않는다.

같은 탭에서 24시간 이내의 유효한 초안만 복구하며 만료·손상 데이터는 작성 창을 열 때 제거한다. 복구는 사용자의 `초안 불러오기`로 본문에만 적용하며 작성자·소속 역할과 인수인계 분류는 현재 선택을 유지한다. 원본 본문이 바뀐 경우 최신 내용과 비교하도록 안내하며 자동 제출하지 않는다. 저장된 초안 삭제는 현재 입력을 지우지 않고, 이후 다시 편집하면 새 초안을 저장한다. 편집 중 본문을 작성 창을 처음 열었을 때의 내용으로 되돌리면 저장된 초안도 지워 지운 내용이 복구되지 않게 한다. 서버 저장 성공 시 해당 초안을 삭제한다. 삭제나 저장이 실패하면 화면에 알리고 서버에 저장된 기록의 성공을 취소하지 않는다. 초안은 서버 기록·멱등 요청 저널과 별개이며 다른 기기·브라우저와 동기화하지 않는다.
